# 兴辰智能产品原型：其他方案参考与克制范围分析报告

> 分析日期：2026-09-19  
> 当前阶段：原型完成后的增量需求评审  
> 本次目标：从“其他方案参考”的12份文档中筛选当前产品真正缺失、能够帮助学校落地使用的最低必要能力；不照搬大而全方案，不修改原型。

## 一、输入材料与真源判断

本次逐份检查了“其他方案参考”目录中的总体架构、MVP范围、SOP Editor、AI Event Engine、SOP State Machine、Assessment Engine、学生/教师端、视频证据、AI Studio、首个PoC和两份竞品分析，共12份文档；同时对照：

- 当前用户最新裁定：只依靠摄像头视频进行判定；摄像头无法判断的评价项默认给分，教师发现问题时再扣分；不接入扭矩传感器等本期外能力。
- 当前原型代码及44条实际路由。
- `AGENTS.md` 中已经确认的产品边界。
- 《高职院校实训操作智能识别与SOP比对系统技术方案V1.0》。
- 全系统审查报告、整改台账和正式验收报告。

项目目录中没有找到名为“PRD V1.1”的独立Markdown文件，只有 `AGENTS.md` 对其34个主页面范围的引用。因此本报告把“最新用户裁定 + 当前有效原型 + 原技术方案 + 已确认整改规则”作为当前需求真源。该缺口不阻碍本轮范围判断，但以后生成正式研发PRD时应补齐或指定原PRD文件。

## 二、执行结论

参考方案的方向大体正确，但范围不适合直接照搬。它把产品扩展成了四个端、九个核心模块、完整Event能力库、AI Studio、模型发布、传感器/PLC/语音、多机位、学生门户和复杂学情分析。对于当前项目，这会把“一个能在学校使用的视觉实训评价系统”扩大成“教学平台 + 感知平台 + MLOps平台”，实施成本和失败风险都过高。

当前原型并不是一个只有展示效果的花瓶。教师/管理员主线已经具备：教师定义SOP、版本冻结、安排准备、工位监控、安全暂停、视频证据、教师复核、成绩发布、导出、异常与审计。真正还缺的是三段落地“最后一公里”：

1. **学生在工位上如何真正开始、完成和恢复一次训练。**
2. **教师如何事先说明每个评价点到底能不能由视频判断，以及不能判断时如何默认计分。**
3. **实施人员在现场如何判断“为什么没有识别成功”，而不必进入一套庞大的AI Studio。**

因此建议不增加完整平台，而只补齐8项P0最低能力、3项P1轻量增强，并明确一组不做项。

## 三、本期产品边界建议

### 3.1 本期最低可落地定义

- 以固定工位、固定RGB摄像头、单人操作、线性SOP为主。
- 支持一个真实实训室先跑通，再用第二套简单SOP验证复用，不追求多专业通用平台。
- 只实现 `Visual Observation + Manual Correction`，不实现传感器、PLC、语音事件接入。
- SOP始终由教师定义；模型不能生成、修改或补写SOP。
- 自动评价只处理摄像头能够稳定观察的事实。
- 摄像头无法判断的质量、力度、精度等评价项默认满分；教师不扣分即保持满分。
- AI不确定、视频遮挡或录像缺失不得自动扣学生分，也不应默认阻塞成绩发布。
- 已明确识别到的安全红线仍可触发受控暂停；系统故障永远不能算学生错误。

### 3.2 建议固定的四类评分结果

| 结果     | 触发条件                                                 | 默认得分      | 是否要求教师处理       |
| -------- | -------------------------------------------------------- | ------------- | ---------------------- |
| 自动通过 | 摄像头可靠观察到完成且无违规                             | 满分          | 否                     |
| 默认通过 | 评价项本身不可由视频判断，或本次证据不足且未发现明确问题 | 满分          | 否，可抽查             |
| 教师扣分 | 教师现场或复盘确认存在问题并填写原因                     | 满分减扣分    | 是，扣分时必填原因     |
| 安全阻断 | 摄像头明确识别到已配置的安全红线                         | 按SOP安全规则 | 是，必须处置后才能继续 |

这里需要明确调整当前原型已有口径：目前“证据不足”通常进入强制待复核并阻塞发布；按照最新裁定，应改成“默认通过/建议抽查”，只有教师主动标记、明确异常或安全事件才进入必须处理队列。

## 四、建议补齐的P0最低能力

### P0-1：步骤“可视频判定性 + 计分策略”

**当前缺口**：SOP Editor有完成条件、证据、扣分和置信度，但没有用教学语言说明“这项能否由摄像头判断、判断不了时怎么办”。教师还直接看到连续确认帧数和最低置信度，过于工程化。

**最小修改**：每个步骤或评价项增加一个“判定方式”：

- 视频自动判定；
- 视频辅助判定，证据不足时默认通过；
- 非视频可判定，默认通过、教师可扣分。

同时显示“自动评价覆盖说明”和已知限制。连续确认帧、置信度等工程参数从教师默认界面移出，只留给实施诊断。

**边界**：不增加扭矩、PLC、语音配置项；对“达到35Nm”只标记为“非视频可判定，默认通过”，不建设传感器产品。

### P0-2：轻量工位训练页，而不是完整学生门户

**当前缺口**：现有原型只有教师端和管理员端。教师可以打开工位、监控学生，却没有学生在工位屏幕上确认身份、开始训练、查看指导、结束训练和断线恢复的真实入口。

**最小修改**：新增一个“工位训练页”，复用教师已分配的学生、工位、任务和SOP快照，不建设“课程社区/消息/LMS”。页面只覆盖：

- 学生、任务、工位确认；
- 摄像头/评价服务/资源准备状态；
- 开始训练或考试；
- 当前步骤、说明、标准内容、计时、进度；
- 请求教师帮助；
- 主动结束及未完成提醒；
- 刷新或短暂断线后恢复同一Session；
- 训练完成后查看本人报告；考试成绩发布前不显示最终分数。

### P0-3：训练与考试的反馈策略真正落到工位端

**当前缺口**：当前教师端区分练习和考试，但没有学生侧行为差异，模式差异主要停留在教师页面和文案。

**最小修改**：

- 训练模式：显示当前步骤、标准操作、错误类型和纠正提示；普通错误页面内提示，不弹窗阻断；连续无法识别时升级为教师关注。
- 考试模式：隐藏实时正确与否、扣分和标准答案；后台仍保存步骤、异常、时间和证据；教师仅处理安全和系统故障，普通复核放到考后。
- 学生“请求帮助”、AI不确定、系统故障统一进入教师监控的关注队列；正常工位继续弱化。

### P0-4：步骤级标准教学内容

**当前缺口**：SOP步骤已有文字规则，但缺少真正供学生训练使用的标准图片、短视频和注意事项；因此系统目前更像评价后台，而不是可用的训练工具。

**最小修改**：每个步骤支持：

- 标准说明；
- 1组标准图片；
- 1段步骤级标准视频或整段视频的起止时间；
- 注意事项/安全提示。

这些内容只在训练模式展示；考试模式默认隐藏。暂不建设素材库、视频剪辑器和自动切片。

### P0-5：工位实施基线与自动评价启用门槛

**当前缺口**：已有设备在线检查和双视角预览，但没有明确管理ROI、机位适用条件、遮挡/光照限制和步骤覆盖情况。模型“已部署”不等于这个工位真的可用。

**最小修改**：在工位/摄像头详情增加一个轻量“实施检查”：

- 当前画面预览；
- 简单矩形ROI：操作区、工具区、危险区；
- 机位、光照、遮挡人工确认；
- 当前SOP可自动判定步骤覆盖表；
- 模型、SOP、ROI和摄像头配置版本；
- 一次现场测试结果。

只有现场测试通过的“视频自动判定项”才启用自动评价；其他项自动降级为默认通过，不阻塞整个SOP使用。

### P0-6：SOP版本的现场验证记录

**当前缺口**：当前发布校验主要检查字段完整、总分和依赖关系，没有验证真实工位上的故意错误与降级分支。

**最小修改**：每个SOP版本在开放自动评价前至少保留以下人工测试记录：

- 标准流程；
- 漏步；
- 错序；
- 错工具；
- 错误后纠正；
- AI不确定/遮挡；
- 摄像头掉线；
- 安全红线。

测试结果只需“通过/失败/不适用 + 说明”，不建设自动化测试平台。SOP业务标准仍可独立发布，但“自动评价可用”必须由现场验证单独确认。

### P0-7：录像完整性与证据有效性

**当前缺口**：当前已有步骤证据、异常视频和保留期限，但没有把“完整、部分缺失、不可用”作为正式业务状态，也没有明确证据缺失时的评分规则。

**最小修改**：

- 每个Session显示录像状态：完整 / 部分缺失 / 不可用；
- 每个步骤保留视频时间范围、摄像头、SOP/模型/ROI版本；
- 视频缺失产生系统异常，不产生学生扣分；
- 完整录像删除后保留步骤、成绩、教师修改和审计记录；
- 训练与考试视频允许不同保留期限；
- 学生只能看本人视频，教师只看负责范围，管理员按授权只读查看。

### P0-8：实施诊断“为什么没有识别成功”

**当前缺口**：当前模型和Dataset信息较多地暴露在教师SOP编辑流程中，但真正需要的现场诊断能力反而不足。发生“步骤没触发”时，实施人员难以区分是摄像头、ROI、模型、规则还是SOP配置问题。

**最小修改**：增加一个只给实施/技术人员使用的轻量诊断页或抽屉：

- 选择Session和步骤；
- 显示完成条件逐项满足情况；
- 显示最近观察事实和时间线；
- 显示摄像头、ROI、模型、SOP版本；
- 给出未触发原因：未看到对象 / 动作不足 / 区域不符 / 证据中断 / 配置缺失；
- 对教师误判反馈标记根因：模型、ROI、SOP配置、系统、非AI问题、未知。

不建设完整Event能力库、在线训练、GPU调度或MLOps后台。教师只看“自动评价可用/部分覆盖/不可用”和已知限制，不操作模型部署、回滚或技术阈值。

## 五、建议列为P1的轻量增强

### P1-1：实训项目最小分组

增加一个很轻的“实训项目”对象，用来归集同一项目的训练SOP、考试SOP、安排和历史记录。当前不必新增完整专业/课程管理页面，可在SOP和安排中增加项目字段与筛选。这样可以避免SOP、练习、考试长期成为互不关联的平铺列表。

### P1-2：班级分析只保留教师真正能用的指标

在现有统计基础上补充：确认后的高频问题、困难步骤、教师介入次数、建议抽查数量、学生列表。只使用最终确认结果，不用AI原始误判直接生成教学结论；不做能力雷达、排名、全校驾驶舱和LLM诊断。

### P1-3：第二套SOP复用验收

这是项目验收资产，不必做成复杂前台页面。记录第二套SOP复用了多少步骤规则、视觉对象、ROI模板和模型能力，以及新增配置工时。它用来判断系统是不是平台，而不是给学校日常用户增加功能。

## 六、明确不纳入本期

以下内容可以在数据结构或技术架构中预留类型，但不应进入当前产品原型和一期研发范围：

- 扭矩传感器、PLC、IoT、ASR和设备控制接入；
- 完整AI Event/对象/区域能力库前台；
- 自研标注工具、训练调度、GPU管理、模型仓库、灰度发布；
- 通用动作大模型、VLM长视频理解、自然语言生成SOP；
- 多机位同步判定、深度相机、3D姿态和开放世界工具识别；
- 复杂分支、并行、循环、多人协作和BPMN；
- 完整学生LMS、课程社区、消息中心、家长端；
- 正式考试申诉仲裁、双教师盲评；
- 复杂能力画像、学业预测、学生排名、全校大数据驾驶舱；
- 典型案例库、跨校资源市场、SOP商城；
- 自动生成教学建议、教师AI助手和数字人。

## 七、参考方案中应保留的架构原则

即使不建设那些大模块，以下关系仍应保留：

1. 摄像头观察事实、SOP业务判定和评分结果分层保存。
2. SOP、Dataset、模型和工位配置分别版本化，运行时锁定快照。
3. 业务异常、AI不确定和系统异常三者分开。
4. 系统异常、视频缺失和AI不确定不自动扣学生分。
5. 教师扣分必须留原因、操作者、时间和原结果。
6. SOP业务发布与自动评价启用分开。
7. 当前实现只支持视觉和人工修正，未来其他来源不在教师页面中伪装成已可用。

## 八、建议确认清单

建议本轮只确认以下三组裁定：

1. 是否接受8项P0作为下一轮原型改造范围；
2. 是否接受3项P1先进入计划、不立即实施；
3. 是否确认“AI不确定/摄像头不可判断/视频缺失默认给分且不阻塞发布，教师主动扣分才改变成绩”为统一评分口径。

确认后再输出分批行动指南，包括页面影响、数据对象、业务规则、实现顺序和逐批验收标准。本报告阶段不开始修改原型。
