# 兴辰智能产品原型：8 项 P0 整体验收与边界回归报告

> 验收日期：2026-09-19  
> 验收范围：已确认的 P0-1 至 P0-8、关键业务边界、角色边界、窄屏适配、自动化规则与生产构建  
> 验收方式：浏览器真实走查 + DOM/交互校验 + 截图证据 + 业务规则自动化测试 + 生产构建

## 一、验收结论

本轮结论为：**有条件通过，暂不能宣布 8 项 P0 全部最终验收通过。**

- 8 项 P0 的页面、数据表达和主要业务闭环均已实现。
- P0-1、P0-2、P0-3、P0-4、P0-5、P0-6 的核心功能通过。
- P0-7 的录像完整性、缺失不扣分、版本和留存策略通过，但“学生只看本人、教师只看负责范围、管理员按授权只读”的真实授权仍未落地。
- P0-8 的诊断信息、根因分类和只读业务边界通过，但管理员专属访问边界未通过：当前角色由 URL 判断，直接访问 `/admin/...` 即显示管理员身份和页面，没有真实的角色路由保护。
- 自动化业务规则测试 28/28 通过，Vite 生产构建与 Sites 构建准备通过。
- 发现 1 项 P0 阻断问题、1 项 P1 业务表达问题、1 项 P2 工程优化项。

因此，产品能力已达到“可以继续演示和联调”的水平；在补上角色与数据访问控制前，不建议把 P0-7/P0-8 视为可用于真实学校环境的最终完成态。

## 三、关键边界回归

### 1. 摄像头能力边界

- 不可从画面可靠判断的扭矩、力度、精度类要求可配置为“视频不可可靠判定，默认通过”。
- 页面没有伪装成已接入扭矩传感器、PLC 或语音设备。
- 自动评价未启用、AI 不确定或录像缺失时，不产生自动扣分。
- 已确认安全红线不会被“默认通过”覆盖。

结论：通过。

### 2. 工位现场门槛与版本变化

- 自动评价必须同时满足实施检查、现场验证和版本一致。
- 现场验证失败的工位只降级自动评价，不阻塞整个 SOP。
- 自动化测试覆盖 ROI、摄像头、模型版本变化后自动评价失效。

结论：通过。

### 3. 训练、考试和发布边界

- 训练模式显示标准内容、纠正提示和实时成绩。
- 考试模式发布前隐藏答案与成绩的规则测试通过。
- 已发布考试显示最终总分和逐步骤得分。
- 证据不足的默认通过结果不会阻塞发布；待复核或缺少必要证据的正式成绩仍会阻塞发布。

结论：通过。进行中考试的视觉态本轮受当前持久化数据限制，采用规则测试补证。

### 4. 录像缺失与安全例外

- 部分缺失时，页面明确系统异常不作为学生扣分依据。
- 主视角可用、辅助视角缺失分别表达，不把“部分缺失”伪装成“完整”。
- 缺失录像不追加扣分，但已确认安全红线仍保持阻断和强制复核。
- 完整录像到期后，步骤结果、成绩版本、教师修改和审计记录继续保留。

结论：业务规则通过；授权边界未完成。

### 5. 角色与权限边界

浏览器实测和代码核对均确认：`Shell` 依据 `pathname.startsWith("/admin")` 决定显示管理员身份与导航，路由表没有角色守卫。由教师页面直接输入 `/admin/workstations/w2` 可进入管理员工位详情，并自动显示“系统管理员”。

结论：未通过。这不是单纯的演示文案问题，而是 P0-7 证据访问范围和 P0-8 管理员专属诊断共同依赖的前置能力。

### 6. 响应式边界

在 820×900 视口下回归管理员诊断、SOP 编辑和学生工位页：

- 三个页面的 `documentElement.scrollWidth` 均未超过 `innerWidth`；
- 管理端侧栏自动收起，核心操作仍保留可访问名称；
- 工位页信息顺序和主操作没有丢失。

结论：通过窄屏基本可用性回归。未进行手机级 360px 适配验收，本产品也不以手机作为工位主终端。

### 7. 可访问性快速检查

- 核心按钮、身份菜单、通知、表单控件具备可访问名称；
- 新增现场验证使用命名 `dialog`，8 个场景控件均有独立标签；
- 必填校验使用 `alert` 输出，根因和验证表单均能提供明确错误文案。

结论：核心结构通过。本轮没有完成完整 WCAG 色彩对比、屏幕阅读器和全流程键盘焦点陷阱测试，不应宣称已通过正式无障碍认证。

## 四、问题清单

### P0-阻断：管理员专属能力没有真实角色路由保护

- 影响步骤：P0-7、P0-8，以及管理员运行配置、工位管理等全部管理页面。
- 复现：在教师端直接访问 `/admin/workstations/w2` 或 `/admin/practices/p1`，页面可直接加载，并按 URL 把当前身份显示成“系统管理员”。
- 根因：角色是 URL 派生的视觉状态，不是登录会话中的授权状态；路由没有 `RequireRole` 一类守卫。
- 风险：教师或其他已进入系统的人可查看管理员诊断、录像状态与配置，并可能调用管理操作；“管理员按授权只读查看”没有形成产品闭环。
- 最小整改：在原型数据层增加当前登录身份与权限；对 `/teacher/*`、`/admin/*` 和录像对象分别做角色/负责范围守卫；无权限时进入 403 页面或返回对应工作台；身份切换只允许模拟登录身份，不允许路径自动抬升权限。
- 验收标准：教师直接输入任意 `/admin/*` 均被拦截；管理员进入教师页时保持管理员身份且只读或按明确授权访问；学生工位端不能枚举其他 Session/学生录像。

### P1：进行中练习把“未进行步骤”计入“有效扣分”

- 影响页面：`/teacher/practices/p1/students/s1`。
- 现象：Session 尚在进行，完成 3/6、当前 35 分，但概览显示“有效扣分 -65”；未进行的 Step 04–06 被等同于已扣分。
- 风险：教师会误以为学生已产生 65 分有效扣分，与“过程记录”和默认通过口径冲突。
- 建议：进行中状态改为“当前已确认扣分”，只统计已完成/已复核步骤中的明确扣分；未进行步骤不进入扣分统计。结束后再显示最终有效扣分。

### P2：生产包体积提示超过 500 kB

- 现象：主 JS 包约 566.71 kB，Vite 给出 chunk size warning。
- 影响：不阻断原型，但真实校内部署到弱网或低配工位时会增加首屏等待。
- 建议：在进入研发实现阶段按教师端、管理员端、工位端做路由级懒加载，不建议为了原型提前过度优化。

## 六、自动化与构建结果

- 业务与站点规则测试：28 项通过，0 失败。
- 已覆盖：默认通过、录像缺失不扣分、安全红线例外、训练/考试反馈差异、现场验证门槛、版本失配降级、诊断原因、异常关闭双确认、运行配置范围、SPA 路由回退和 Sites 打包。
- Vite 生产构建：通过，1735 个模块完成转换。
- Sites 构建准备：通过，生成 `dist/server/index.js` 与 `dist/.openai/hosting.json`。
- 唯一构建提示：主 JS chunk 超过 500 kB，为 P2 性能优化项，不影响本轮功能验收。

## 七、建议的收口顺序

1. 先补角色会话、路由守卫和录像对象访问范围，这是 8 项 P0 真正完成的前提。
2. 修正进行中报告“有效扣分 -65”的统计口径。
3. 再跑一次针对权限的四角色回归：教师、管理员、工位学生、未登录。
4. 权限回归通过后，把本报告结论更新为“8 项 P0 全部通过”；P2 包体积可进入后续研发优化，不阻塞原型收口。
