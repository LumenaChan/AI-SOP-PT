# 兴辰智能产品原型：全系统深度审查报告

> 审查日期：2026-09-18  
> 阶段：交互原型验收前的产品与功能审查，不是生产系统安全认证  
> 结论：页面框架已较完整，但尚不具备“功能完整、操作有效、业务闭环”的验收条件。  
> 本轮边界：仅审查、取证和形成整改建议；不修改原型。以下清单待产品负责人确认后实施。

## 一、执行摘要

当前原型的主要问题不是缺少漂亮页面，而是**展示层与业务对象、权限、状态之间没有可靠连接**。很多按钮能够点击，但点击后没有产生可验证的业务结果。

本次结合浏览器实际操作、截图和当前源码核对，覆盖了 **37 个业务路由模板的代表页面**，包括登录、教师端、管理员端。共归并 **40 组问题：P0 6 组、P1 32 组、P2 2 组**。同一共性问题可能影响多个按钮或页面，不按按钮数量重复计数。这是问题清单，不是完成率统计。

最重要的结论：

1. **新建、保存、复核、结束、发布、导出大量停留在成功提示。** 不能将“弹窗能打开”或“提示成功”作为功能完成。
2. **对象关联存在错误。** 从李思雨的监控进入报告，实际显示张浩；其他学生、工位、设备也存在固定打开第一条记录的问题。
3. **权限边界在页面跳转时丢失。** 管理员标为只读的考试记录，点击查看后进入教师身份的结果页，出现“统一发布”等操作。
4. **“教师定义 SOP，模型只识别，状态机判定”的方向正确，但尚未落实。** 步骤编辑丢失、新增步骤未进入映射、未审核却显示已签名，业务真源仍是静态演示文案。
5. **安全与成绩结论不可信。** 故障工位仍显示正常识别和允许进入；待复核未清零却可统一发布；复核选择保留扣分，预览却显示加分。
6. **班级问题是共性问题的一个入口。** 教师、班级、学生、工位、设备管理均有类似的重复入口、简化表单、占位详情或无保存闭环。

### 已做得好的部分，建议保留

- 教师端与管理员端的导航划分清晰，整体视觉风格一致，主要业务页面均可访问。
- 单工位监控的大视频、底部全部 SOP 步骤、右侧结果与用时布局符合此前明确的产品方向。
- SOP 页面已经明确专业教师的标准责任、固定 Step ID、Other 类，以及 SOP 与模型独立版本的概念。
- 个人报告已呈现“标准要求—观察事实—触发规则—分数影响”，这是正确的证据表达结构。
- 已考虑复核理由、证据归档、分数影响预览、版本差异提示及故障时间线；下一步应把这些设计转化为真实可操作的原型流程。

## 二、审查依据与结论边界

### 2.1 依据

- 当前对话中的产品要求，包括班级字段、全部功能可用性、单人监控布局，以及 SOP 不由模型生成。
- 用户提供的《高职实训操作智能识别与 SOP 比对系统技术方案》V1.0，重点为 §3.1；本轮不对其引用的 GitHub 项目重新做技术选型验证。
- 当前原型 `src/App.jsx`、`src/styles.css`、项目 `AGENTS.md`，以及本轮实际访问的页面。
- 本轮新生成的截图与 DOM 记录，保存在 `audit-product-2026-09-18`；不以旧审查结论代替本次证据。

### 2.2 判断标准

原型允许使用模拟数据，不要求本轮接入真实摄像头、后端、训练平台或真实账号系统。但至少应该做到：

> 正确入口 → 完整输入 → 有效校验 → 明确确认 → 对象/状态发生改变 → 列表和关联页面同步 → 可以回看结果。

如果功能尚未实现，应明确禁用并说明范围，不能以“已完成/已保存/已发布”替代实际结果。

证据标记：**B** = 浏览器复现；**C** = 当前源码直接确认；**R** = 产品补齐建议。报告将既有缺陷与建议分开，不把所有新增建议说成已承诺需求。

### 2.3 限制

- 37 个业务路由模板均检查了代表页面；并不等于逐个穷举所有对象、所有数据组合、所有异常分支。
- 主要截图视口为 1280×720，起始用户页面为 1180×704。本轮不宣称完成 827px、所有大屏尺寸或移动端适配验收。
- 未进行真实设备联调、模型准确率验证、压力测试、网络中断注入、服务端权限测试。
- 未进行完整键盘遍历、读屏和颜色对比度测量，因此只报告已见无障碍风险，不宣称符合 WCAG。
- 项目约定提到“34 个主页面”，但当前工作区未找到完整 PRD V1.1 原文，无法逐条核对原 PRD 的全部需求。这里以当前实际路由和明确产品裁定为基线。
- 当前自动化测试的 4 个用例只检查静态资源、SPA 回退、API/写请求处理和构建产物，**不能作为业务功能完成的证明**。

## 三、六项验收阻断问题（P0）

这里的 P0 指“阻断本轮产品原型验收、容易指导研发做错”，不等于已经发生生产事故。

### 1. 成功提示没有对应业务结果【B+C】

**复现**：班级新建未填写名称直接确认，提示“新建班级已保存”，列表仍为原有记录；练习点击结束并确认，提示“安排已结束，正在生成报告”，页面仍为进行中。

**根因范围**：公共 `Shell.finish` 仅关闭弹窗和设置提示文字，没有执行表单提交或业务状态修改。大量保存、复制、发布、复核、导出流程复用了该机制。

**影响**：用户无法判断结果是否生效，也无法从新建走到使用、从结束走到报告。

**验收要求**：每个写操作必须有明确业务处理、唯一对象 ID、关联刷新及失败反馈；提交失败不能显示成功。只读说明弹窗使用“知道了/关闭”，不伪装成业务确认。

证据：04、53、58；代码：`App.jsx:539`、`App.jsx:695`。

### 2. 查看对象与进入对象不一致【B+C】

**复现**：考试 2 号工位显示李思雨，点击“查看学生报告”，进入“考试个人报告 · 张浩”。管理员学生列表点击李思雨同样打开张浩。源码中学生、工位、设备详情和多个结果详情使用固定 ID 或固定内容。

**影响**：可能看错证据、改错成绩、配置错设备；这是对象安全与业务正确性的基础问题。

**验收要求**：列表、详情、监控、报告、导出、日志均使用同一组实体 ID；至少以两个不同对象交叉验收；对象不存在应显示失效页，不能回退到第一条数据。

证据：[李思雨监控](</Users/chenxuguang/Documents/ChatGPT/AI SOP 实训评价/xingchen-prototype/audit-product-2026-09-18/50-exam-student-monitor.png>) → [实际打开张浩报告](</Users/chenxuguang/Documents/ChatGPT/AI SOP 实训评价/xingchen-prototype/audit-product-2026-09-18/51-li-opens-zhang-report.png>)；代码：`StudentMonitorPage:1227`、`Report:2831`、`AdminList:3239`、`AdminDetail:3299`。

### 3. 管理员“只读”在跳转后变成教师可操作页面【B+C】

**复现路径**：管理员 → 考试记录 → 查看期中考试 → 教师身份的考试结果页 → 可点击“统一发布”。

**实际问题**：身份来自 URL 前缀，查看动作改变了角色上下文。这不同于用户明确选择“切换身份”。

**验收要求**：角色与路由分离；管理员查看教学数据全过程保持只读，包括二级详情、复核、导出和视频；教师只能操作授权范围。演示身份切换可保留，但必须是明确动作。

证据：21、22；代码：`Shell:695`、`AdminRecords:3387`。本项是原型权限流程缺陷，不是服务端漏洞测试结论。

### 4. SOP 的业务真源没有真正建立【B+C】

**复现**：

- “创建 SOP”进入预填的“编辑工业机器人末端夹具更换”，默认跳过基础信息。
- 将 Step 04 名称改为新名称，切换到 Step 03 再切回，输入丢失。
- 新增 Step 06 后，数据映射仍固定 Step 01–05。
- 直接点击审核发布，仍显示“专业教师已签名”“5 个操作步骤”“已满足发布条件”；没有实际签名动作或规则校验。

**影响**：后续识别、评分引用的并不是教师最终确认的同一份标准；“SOP 不由模型生成”会退化成一句说明。

**验收要求**：教师定义、状态机、映射和审核摘要读取同一份 SOP 草稿；Step ID 稳定；变更实时保留；发布检查真实计算；签名记录责任人、时间、版本和确认行为。发布后冻结，修改走新版本。

**复现**：异常详情说明 1 号工位“实时评价已受控暂停”；同工位监控仍显示 LIVE、92% 置信度、“状态机：顺序合法”“允许进入”，按钮还是“暂停评价”。

**验收要求**：

- 工位故障、安全暂停、人工暂停分别建状态；录像可继续，不代表自动评价可继续。

- 红线触发后展示阻断原因、影响范围、教师/管理员处理责任及恢复条件。
- 模拟场景也必须让监控、事件、准备页和故障详情一致。

### 6. 人工复核和正式成绩发布没有可信门槛【B+C】

**验收要求**：结论、证据、理由、分数联动；空白理由、越界分数、未处理的阻断项不能通过；正式发布依据同一批学生记录计算，不使用固定文案。成绩变更保留原判、有效判、操作者、时间、证据及修订历史。

## 六、产品逻辑闭环应如何收敛

不建议为每个按钮独立制作更多弹窗。应先确定对象关系，再让页面引用同一数据和状态。

### 6.1 对象及版本关系

| 上游对象 | 下游引用 | 必须保持的一致性 |
| --- | --- | --- |
| 班级、学生、教师 | 安排名单、责任教师 | 当前资料可更新；历史参与信息有快照 |
| SOP版本与固定Step ID | Dataset标签、模型输出映射、评分规则 | 模型不能新增/改写业务步骤；映射引用版本 |
| 模型版本 | 部署工位、自动评价能力 | 单独审核、兼容检查、上线与回滚 |
| 安排 | 名单、工位、SOP快照、模型快照 | 首次开放锁定；准备/监控/结果不换ID |
| 学生会话 | 动作事件、步骤评价、媒体证据、报告 | 工位可以换学生；历史会话不能被覆盖 |
| 人工复核 | 有效评分、正式报告、审计、候选样本 | 原始识别事实保留；纠正成绩不自动重写标准 |
| 发布批次 | 结果快照、导出产物 | 同一版本、同一名单口径；后续更正可追溯 |

### 6.2 建议状态规则

以下状态名是建议，待确认后进入实现，不是声称当前已存在。

1. **SOP**：草稿 → 待审核 → 已发布 → 停用。审核退回回到草稿；已发布不能原地改写。
2. **Dataset**：采集中 → 待审核 → 已锁定。新增或纠正样本进入下一版，不静默改写已锁定版本。
3. **模型**：待训练 → 训练中 → 待验证 → 可部署 → 已部署；失败可重试，回滚到兼容版本。模型未就绪不阻止业务标准单独发布，但阻止自动评价开放。
4. **安排**：草稿 → 待开始/准备中 → 进行中 ↔ 已暂停 → 已结束。考试结果另有生成中 → 待复核 → 可发布 → 已发布。
5. **工位与会话**：工位开放 ≠ 学生已开始；设备健康、入场资格、会话执行状态分开。学生结束后进入待复位，复位确认后才能接待下一位。
6. **步骤执行与判定**：执行状态（未进行/进行中/已结束/跳过等）与判定（通过/不通过/待复核/证据不足）分开，避免把“不通过但已结束”当作安全前置条件已满足。
7. **异常**：新发现 → 处理中 → 技术恢复待复查 → 已解决；业务恢复由相应责任人确认，不能仅凭写入一条说明自动放行。

### 6.3 实时监控的产品修正方向

保留现在的大视频布局。补齐的重点是语义和真实性：

- 明确“现场当前动作”与“正在查看的历史步骤”，两者互不篡改。
- 视频主辅来源、时间、延迟/离线状态可见；演示素材明确标识，不把工厂装配示意图当作真实汽车高压作业证据。
- SOP 步骤全部展示，未进行显示无结果/无用时；进行中显示累计用时；已结束分别显示通过、不通过或待复核。
- 右侧统计按当前学生会话计算；步骤详情展示规则、观察事实、时长、分数、证据。
- Other 是候选类别，不等于自动判错；证据不足进入复核；确认的安全风险进入受控暂停。
- 高风险“恢复评价”必须能解释谁确认、依据什么、哪些前置条件已经重新满足。

## 七、需要确认的业务决策

以下事项会影响页面和数据模型，但不妨碍先修复已经确定的重复入口、错对象和无效控件。建议确认整改范围时一并裁定，不默认扩展为复杂平台。

| 决策点 | 建议默认方向 | 为什么需要明确 |
| --- | --- | --- |
| SOP发布审核责任 | 先支持有权限的专业教师明确确认并签名；是否另设第二审核人由学校决定 | 不应擅自假设必须双人审核，也不能无操作显示已签名 |
| SOP与自动评价能力 | 标准可独立发布；只有兼容模型已验证部署后才能开放自动评价 | 避免把模型训练状态当成标准有效性 |
| 正式成绩发布门槛 | 已参加学生无生成中/阻断复核项才可发布；未参加单独标识 | 是否允许部分发布、缺考记分、发布后更正需单独规定 |
| 证据不足如何评分 | 保留暂定结果和待复核状态，不冒充正式失败结论 | 不确定性不能被隐藏在总分中 |
| 练习与考试差异 | 共用基础流程，分别明确反馈可见性、次数、入场窗口与成绩规则 | 目前主要差异是文案；还需限定学生端看到什么 |
