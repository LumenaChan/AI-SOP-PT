# 视频证据链 + 训练复盘 + 学情分析详细设计

**版本：V1.0**  
**所属产品：AI 实训智能指导与考评平台**  
**模块定位：将训练全过程中的视频、步骤、事件、异常、教师介入和评分结果组织成可追溯、可复盘、可统计的教学数据资产**

---

# 一、模块定位

前面的系统已经能够完成：

```text
识别操作
↓
判断步骤
↓
发现异常
↓
实时提示
↓
自动评分
↓
教师复核
```

但如果最终只留下：

```text
成绩：82分
完整录像：18分钟
```

那么大量过程数据的价值都没有真正发挥出来。

这一模块需要解决三个问题。

第一：

> **发生了什么，证据在哪里？**

第二：

> **学生应该如何复盘？**

第三：

> **老师如何从30名学生、几十次训练中发现共性教学问题？**

因此这一层不是单纯的视频管理，也不是传统 BI。

它的核心是：

> **把连续的视频过程结构化成“技能执行轨迹”。**

---

# 二、整体数据关系

一场完整训练最终应该形成：

```text
Training Session
│
├── 原始视频
│
├── SOP步骤轨迹
│
├── AI Event
│
├── Step Runtime
│
├── Exception
│
├── Feedback
│
├── Teacher Intervention
│
├── Assessment
│
└── Learning Metrics
```

然后生成三类结果：

```text
个人复盘
班级分析
课程/项目分析
```

---

# 三、什么叫“视频证据链”

视频证据链不是：

> 给一场训练保存一个 MP4。

真正的证据链应该能够从任何一个业务结果反向追溯到原始操作过程。

例如：

```text
最终成绩 84
↓
S07 得3分
↓
错误工具 -2
↓
WRONG_TOOL
↓
AI检测到 open_end_wrench
↓
02:18 视频
↓
对应摄像头
↓
对应AI Event
↓
对应模型版本
↓
教师复核结果
```

这整条链才叫：

> **Evidence Chain**

---

# 四、Evidence 对象

建议系统独立定义：

```text
Evidence
```

而不是在异常里只存一个视频 URL。

一个 Evidence 至少包含：

```text
evidenceId
sessionId
stepId
eventId
exceptionId
cameraId
videoId
startTime
endTime
snapshot
sourceType
```

例如：

```json
{
  "evidenceId": "evi_001",
  "sessionId": "session_001",
  "stepId": "S07",
  "exceptionId": "ex_002",
  "cameraId": "cam_03",
  "videoId": "video_03_001",
  "startMs": 131000,
  "endMs": 148000,
  "sourceType": "VIDEO"
}
```

---

# 五、为什么 Evidence 要独立

因为一个异常可能存在多个证据。

例如：

```text
WRONG_TOOL
```

可以有：

```text
正视相机
顶视相机
AI对象检测结果
教师现场确认
```

所以未来关系应该允许：

```text
Exception
↓
Evidence[]
```

而不是：

```text
Exception
↓
videoUrl
```

---

# 六、Evidence 类型

一期建议支持：

```text
VIDEO_CLIP
SNAPSHOT
AI_EVENT
MANUAL_NOTE
```

后期扩展：

```text
SENSOR_DATA
DEVICE_LOG
SPEECH_TRANSCRIPT
```

例如扭矩场景：

```text
视频证据
+
扭矩曲线
```

共同证明：

> 操作是否符合要求。

---

# 七、完整视频与证据片段要分开

每场 Session 保存：

```text
完整原始视频
```

同时根据步骤和异常自动生成逻辑片段。

例如：

```text
S07 操作片段：
02:02–02:34

WRONG_TOOL异常：
02:14–02:23
```

这里“片段”不一定需要真的重新编码生成一个新视频文件。

一期完全可以保存：

```text
videoId
+
startTimestamp
+
endTimestamp
```

播放时直接定位。

这样节省大量存储。

---

# 八、视频时间轴

结构化视频播放器是这个模块最重要的前台能力之一。

建议时间轴分三层：

```text
步骤轨
异常轨
教师/系统事件轨
```

例如：

```text
00:00 ───────────────────────────────────── 10:42

步骤
[S01] [S02] [----S03----] [S04] [-----S05-----]

异常
             ⚠错工具                ⚠超时

教学事件
                   💬系统提示
                        👨‍🏫教师确认
```

用户可以直接点击节点跳转。

---

# 九、时间轴默认不要展示 AI 原始事件

不要让教师默认看到：

```text
OBJECT_APPEAR
HAND_TOUCH_OBJECT
RELATION_START
```

这些属于调试数据。

教学时间轴默认展示：

```text
步骤
异常
提示
教师介入
系统异常
```

只有进入：

> AI 调试模式

才显示原始 Event。

---

# 十、步骤片段

每个 Step 自动形成一个时间段：

```text
readyAt
startedAt
completedAt
```

视频片段建议优先使用：

```text
startedAt - buffer
到
completedAt + buffer
```

例如：

```text
前2秒 + 操作过程 + 后2秒
```

方便复盘完整动作。

---

# 十一、异常片段

异常片段应该比步骤片段更短。

例如：

```text
异常发生前5秒
+
异常过程
+
异常后5秒
```

这样教师点击异常后可以快速看懂发生了什么。

不同异常可采用不同窗口。

例如：

```text
工具错误：前3秒 / 后5秒
错序：前8秒 / 后8秒
安全违规：前10秒 / 后10秒
```

一期可以统一使用：

> 前5秒 + 后5秒。

---

# 十二、视频播放器页面布局

建议：

```text
┌────────────────────────────────────────────┐
│ 学生：张三   减速器拆装   训练3            │
├──────────────────────────┬─────────────────┤
│                          │ 当前节点         │
│                          │                 │
│        视频播放器         │ S07紧固螺栓     │
│                          │                 │
│                          │ 工具错误 -2      │
│                          │                 │
│                          │ [标准操作]       │
├──────────────────────────┴─────────────────┤
│ 时间轴                                     │
│ S01 S02 ⚠S03 S04 ...                     │
├────────────────────────────────────────────┤
│ [全部] [异常] [教师介入] [系统提示]        │
└────────────────────────────────────────────┘
```

---

# 十三、播放器右侧信息

根据当前时间点动态显示：

```text
当前步骤
步骤要求
实际结果
异常
得分
教师处理
```

例如：

```text
步骤：
S07 使用扭矩扳手紧固螺栓

标准：
扭矩扳手

实际：
开口扳手

异常：
工具选择错误

AI判断：
已确认

教师复核：
确认AI判断正确

扣分：
-2
```

---

# 十四、标准操作对照

点击：

> 标准操作

建议支持：

```text
本次操作
标准视频
```

左右对照。

例如：

```text
┌─────────────┬─────────────┐
│ 我的操作     │ 标准操作     │
│             │             │
│ 视频         │ 视频         │
└─────────────┴─────────────┘
```

一期不需要同步骨架对比。

先解决：

> 学生能方便地自己看出差异。

---

# 十五、对照播放方式

建议支持：

```text
同时播放
分别播放
重新开始
```

如果两段时长不同：

> 不强制严格时间同步。

一期先保证简单易用。

---

# 十六、错误复盘卡片

学生报告中每个错误建议形成一张卡片。

例如：

```text
步骤7｜紧固端盖螺栓

问题：
工具选择错误

标准要求：
扭矩扳手

本次操作：
使用开口扳手

扣分：
-2

[查看我的操作]
[查看标准操作]
```

不要把错误列表写成：

```text
WRONG_TOOL
S07
-2
```

---

# 十七、学生复盘顺序

学生进入训练报告后，建议优先看：

```text
本次关键问题
↓
问题视频
↓
标准操作
↓
完整步骤明细
↓
能力表现
```

而不是一上来先给雷达图。

学生真正最需要的是：

> 我具体哪里错了。

---

# 十八、关键问题筛选

一场训练可能产生很多记录。

不能全部标成：

> 关键问题。

建议优先展示：

```text
安全问题
严重扣分项
重复发生异常
漏步
错序
错误工具
教师特别标记
```

普通轻微超时可以放后面。

---

# 十九、同类异常合并

例如：

```text
WRONG_TOOL
连续发生3次
```

报告中可以展示：

> 工具选择错误 ×3

点击再展开：

```text
第一次 02:18
第二次 03:41
第三次 05:22
```

避免报告太碎。

---

# 二十、教师点评与视频节点关联

教师可以针对某一异常或步骤添加点评。

例如：

```text
“工具已经选对，但握持位置不规范。”
```

绑定：

```text
S07
02:18
```

学生点击点评：

> 自动跳到对应视频。

这样教师点评更具体。

---

# 二十一、教师不需要手动剪视频

教师只需：

```text
暂停到某时间点
点击“添加点评”
输入文字
```

系统自动记录：

```text
timestamp
```

后期可以扩展语音点评。

一期文字即可。

---

# 二十二、训练报告总览

建议顶部核心指标保持简单：

```text
训练成绩
完成步骤
操作用时
异常次数
重试次数
提示次数
```

例如：

```text
成绩            86
步骤完成        11 / 12
总用时          08:42
异常            3
重试            2
系统提示        4
```

---

# 二十三、训练报告不要一开始给太多百分比

例如：

```text
操作稳定度 78.32%
动作规范指数 83.17%
```

如果这些指标没有清晰教学定义，会让报告显得“AI味很浓但不可信”。

一期指标应尽量可解释。

---

# 二十四、步骤明细

每一步展示：

```text
步骤名称
完成状态
得分
操作时长
异常
提示次数
```

例如：

| 步骤     | 状态  | 得分   | 用时  | 异常  |
| ------ | --- | ---- | --- | --- |
| 检查PPE  | 完成  | 5/5  | 12s | 无   |
| 检查工具   | 完成  | 5/5  | 21s | 无   |
| 拿取扭矩扳手 | 完成  | 3/5  | 18s | 错工具 |
| 紧固螺栓   | 完成  | 8/10 | 38s | 超时  |

点击进入视频。

---

# 二十五、步骤耗时如何解释

不要简单写：

> 比平均慢32%。

可以更教学化：

```text
本次：
38秒

班级中位数：
26秒
```

教师据此判断。

学生端可以简化为：

> 本步骤用时偏长。

但不要直接等同于能力差。

---

# 二十六、历史训练对比

同一个学生多次训练同一 SOP：

```text
训练1
训练2
训练3
训练4
```

建议比较：

```text
成绩
异常次数
提示次数
重试次数
总用时
```

例如：

```text
成绩      68 → 79 → 86 → 92
异常      6  → 4  → 3  → 1
提示      9  → 6  → 4  → 1
用时      13:20 → 11:05 → 09:42 → 08:58
```

---

# 二十七、这种趋势比一次高分更有教学价值

系统能够回答：

> 学生是否在进步。

而不仅仅：

> 这次多少分。

尤其训练场景，趋势指标应该比班级排名更重要。

---

# 二十八、同版本优先比较

历史趋势默认优先比较：

> 同一个 SOP Version。

如果版本不同，页面要明确标记：

```text
V1.0
V1.1
```

不要隐藏规则变化。

---

# 二十九、个人能力画像一期怎么做

一期建议只基于明确映射的 Assessment Item 聚合。

例如：

```text
安全规范       95
流程规范       78
工具使用       82
操作规范       86
完成质量       88
操作熟练       74
```

不要让 LLM 主观判断。

---

# 三十、能力画像的数据来源必须可解释

点击：

> 工具使用 82

可以展开：

```text
S03 工具选择     5/5
S07 工具选择     3/5
S09 工具归位     4/5
```

让老师知道：

> 82 是怎么来的。

---

# 三十一、能力画像展示方式

一期建议：

```text
条形图
```

或者：

```text
雷达图 + 数值
```

但不要只有雷达图。

必须同时展示具体数值和来源。

---

# 三十二、能力趋势

同一个学生多次训练后：

```text
工具使用
72 → 78 → 82 → 91
```

可以帮助老师判断：

> 哪项能力正在提升，哪项一直停滞。

一期如果开发量有限，可以二期再做趋势图。

底层数据必须支持。

---

# 三十三、学生个人历史页

建议结构：

```text
个人概览
最近训练
SOP训练历史
能力表现
高频问题
```

例如：

```text
最近30天

训练次数：12
完成：11
平均成绩：84
```

---

# 三十四、高频问题

根据学生历史记录统计：

```text
工具选择错误  7次
操作超时      5次
漏复检        4次
```

这比一次报告更能指导针对性训练。

---

# 三十五、但不能简单跨不同 SOP 合并所有错误

例如：

```text
STEP_TIMEOUT
```

在不同项目里的难度完全不同。

因此统计应至少支持：

```text
按SOP
按课程
按异常类型
```

查看。

---

# 三十六、教师班级分析定位

班级分析的目标不是：

> 做一个很漂亮的数据大屏。

而是回答教学问题：

```text
全班哪里最容易错？
哪一步最难？
哪些学生需要额外指导？
AI在哪些地方频繁需要老师复核？
下一次课应该重点讲什么？
```

---

# 三十七、班级概览

建议：

```text
参与人数
完成人数
平均成绩
合格率
平均用时
教师介入率
```

例如：

```text
参与       30
完成       28
平均成绩   82.4
合格率     87%
平均用时   09:18
介入率     20%
```

---

# 三十八、介入率为什么要放教师分析里

因为它直接体现：

> AI有没有真正减轻教师实时巡查负担。

例如：

```text
30人
只有6人需要教师介入
```

比单纯说：

> AI准确率95%

更能说明课堂价值。

---

# 三十九、高频异常排行

例如：

```text
1. S07 工具选择错误       12人 / 40%
2. S10 漏复检              9人 / 30%
3. S04 操作顺序错误        7人 / 23%
```

教师点击：

> 查看涉及学生。

---

# 四十、高频异常必须同时支持“按异常看”和“按步骤看”

按异常类型：

```text
工具错误
错序
超时
漏步
```

按步骤：

```text
S07
S10
S04
```

因为老师可能想知道：

> 是某类能力有问题，还是某个具体知识点有问题。

---

# 四十一、步骤分析

每一步统计：

```text
完成率
一次成功率
异常率
平均重试次数
平均用时
提示率
教师介入率
```

例如：

```text
S07 紧固螺栓

完成率：96%
一次成功率：58%
异常率：42%
平均重试：1.6
平均用时：41s
教师介入：20%
```

这已经能非常清楚地看出：

> S07 是难点。

---

# 四十二、“一次成功率”是很有价值的指标

定义：

```text
第一次 Attempt 就正确完成的学生
/
执行该步骤学生
```

例如：

```text
18 / 30
= 60%
```

比最终完成率更能反映：

> 学生第一次是否真正掌握。

因为最终完成率可能很高，但很多学生是经过3次提示才完成。

---

# 四十三、提示率

定义：

```text
该步骤收到系统提示的学生数
/
执行人数
```

例如：

```text
S07提示率 43%
```

如果异常率不高，但提示率很高，说明：

> 很多学生依赖系统辅助才完成。

---

# 四十四、教师介入率按步骤统计

例如：

```text
S04 介入率 6%
S07 介入率 28%
S10 介入率 10%
```

可以帮助产品和老师一起判断：

> 哪些步骤 AI 还没有真正减负。

---

# 四十五、困难步骤列表

建议系统自动按多个原始指标排序，但不要立即创造一个“AI难度分”。

可以显示：

```text
S07

异常率       42%
一次成功率   58%
平均重试     1.6
教师介入率   28%
平均用时     41s
```

老师自己判断。

---

# 四十六、班级学生列表

字段建议：

```text
学生
最终成绩
完成率
异常次数
提示次数
重试次数
总用时
状态
```

但不要默认用总分高低给学生做“优劣排名”。

可以提供普通排序筛选。

---

# 四十七、重点关注学生

系统可以按照事实筛选：

```text
未完成
频繁求助
错误次数较多
多次训练仍重复同一错误
教师介入较多
```

但页面名称建议：

> 需要关注

不要：

> 后进学生。

---

# 四十八、“重复错误”比单次低分更重要

例如学生连续三次训练都在：

```text
S07
WRONG_TOOL
```

这应该形成：

> 重复问题提示。

例如：

```text
张三在最近3次训练中均出现“S07 工具选择错误”。
```

这是真正有教学价值的信息。

---

# 四十九、不要一期自动给原因

系统可以说：

> 连续三次发生同一错误。

但不要直接下结论：

> 学生对扭矩工具理解不足。

除非后续有明确教学规则或老师确认。

一期事实优先。

---

# 五十、课程级分析

当一个 SOP 被多个班级反复使用以后，可以上升到课程层。

例如：

```text
机械装配技术
```

统计：

```text
本学期训练人数
训练次数
平均完成率
高频困难步骤
高频异常
```

---

# 五十一、课程级最大的价值

帮助老师判断：

> 课程设计中哪些实训环节长期是难点。

例如：

```text
过去4个班
S07异常率始终 > 35%
```

说明：

> 这不是某个班偶然的问题。

值得重新调整教学。

---

# 五十二、SOP版本效果分析

如果：

```text
V1.0
```

后来优化成：

```text
V1.1
```

系统可以比较：

```text
错误率
平均用时
教师介入率
```

但必须注意：

> 不同学生群体不能简单当严格 A/B Test。

一期先做描述性比较，不做因果结论。

---

# 五十三、AI质量分析与教学分析必须分开

例如：

```text
S07 AI待复核率很高
```

这可能不是学生难。

而是：

> AI能力差。

所以教师分析页面最好同时提示：

```text
教学异常率
AI待复核率
```

如果：

```text
异常率 40%
待复核率 35%
```

就应该谨慎解释。

---

# 五十四、AI待复核率

定义：

```text
REVIEW_REQUIRED次数
/
该步骤执行次数
```

例如：

```text
S07
AI待复核率 18%
```

这个数据主要提供给：

> 产品/技术团队。

教师也可以看简单提示：

> 当前步骤 AI 自动判断稳定性较低。

---

# 五十五、模型问题不要伪装成教学问题

例如：

```text
S05错误率突然从10%升到45%
```

如果同时：

```text
教师驳回率也从2%升到30%
```

更可能说明：

> AI有问题。

所以数据分析后台应该能联动：

```text
教学数据
+
AI质量数据
```

---

# 五十六、教师复核修正率

按步骤统计：

```text
AI异常：100
教师驳回：20
```

则：

```text
修正率 20%
```

如果太高：

> 应标记 AI 能力需要优化。

不要继续把这些 AI 初始判断计入“学生错误率”。

班级教学统计应该优先使用：

> 最终确认后的异常。

---

# 五十七、教学统计使用最终结果

正式统计中：

```text
AI Exception DETECTED
```

不能直接进入最终教学分析。

应该使用：

```text
CONFIRMED Exception
```

以及未复核但达到可靠条件的最终结果。

否则统计会被 AI 误判污染。

---

# 五十八、训练模式即时报告与最终报告

如果存在待复核，可以区分：

### 即时报告

训练结束立即产生。

标记：

> 部分结果待确认。

### 最终报告

教师复核完成后更新。

一期可以不做两个独立版本。

页面显示：

```text
报告状态：待确认
```

复核后变：

```text
已确认
```

---

# 五十九、报告更新不能丢失历史

教师复核后：

```text
86 → 88
```

需要保留：

```text
原AI结果
最终结果
```

但学生默认只看最终结果。

---

# 六十、结构化视频检索

随着训练越来越多，教师最好可以按：

```text
学生
SOP
步骤
异常类型
日期
```

直接找视频。

例如：

> 查看所有“S07工具选择错误”的视频。

这会形成非常有价值的教学案例库。

---

# 六十一、错误案例库

后期可以将典型匿名化片段沉淀为：

```text
典型错误案例
```

例如：

```text
错误工具案例
错序案例
危险操作案例
```

供课堂讲解。

但一期建议先支持：

> 教师收藏某个片段。

---

# 六十二、收藏为教学案例

教师在复盘视频中点击：

> 收藏为案例。

填写：

```text
案例名称
问题类型
备注
```

例如：

> “典型的错误扳手选择”。

后续可以在课程中查看。

一期如果要严格压缩，可放 P1。

---

# 六十三、隐私与权限

视频属于高敏感度教学数据。

权限至少应区分：

```text
学生
教师
课程负责人
管理员
```

学生默认：

> 只能看自己的视频。

教师：

> 看自己负责班级。

管理员：

> 根据权限查看。

不能做：

> 学生互相看彼此全过程视频。

---

# 六十四、视频保存周期

产品上必须支持配置：

```text
原始视频保留天数
结构化结果保留期限
```

例如学校可以配置：

```text
训练视频 90天
考试视频 1年
结构化成绩长期保存
```

具体期限根据学校制度决定。

一期至少要预留配置。

---

# 六十五、训练视频和考试视频生命周期可能不同

正式考试通常要求：

> 保存更久。

所以视频保存策略应该基于：

```text
taskType
```

而不是全系统一个统一天数。

---

# 六十六、删除视频不能删除考评结果

例如视频超过保留期删除。

仍应保留：

```text
Session
Step Result
Assessment
Teacher Review
Audit Log
```

但 Evidence 标记：

```text
VIDEO_EXPIRED
```

而不是整条成绩数据一起消失。

---

# 六十七、视频完整性

正式考试以后最好增加：

```text
录像是否完整
```

例如：

```text
完整
部分缺失
不可用
```

这可以参与：

```text
Assessment Validity
```

一期基础做：

> 是否存在视频、视频时长。

即可。

---

# 六十八、视频与事件时间基准统一

Camera、Event、Runtime 必须尽量使用同一时间基准。

否则：

```text
AI说错误发生02:18
播放器跳到02:21
```

用户会迅速失去信任。

所以这不仅是技术细节，也是核心产品质量。

---

# 六十九、多机位证据链

以后多机位时，一个步骤可以包含：

```text
主视角
俯视
局部特写
```

时间轴共用同一时间。

切换机位不改变：

```text
当前步骤
异常位置
```

---

# 七十、视频预加载

教师点击异常后应该快速打开。

不能每次：

> 等很久才加载几十分钟视频。

技术上可以对异常前后片段做：

```text
关键片段索引 / 预处理
```

具体实现交给技术团队。

产品验收标准：

> 点击异常后能快速进入对应片段。

---

# 七十一、学生报告和教师报告视角不同

学生看：

```text
我哪里错
怎么改
有没有进步
```

教师看：

```text
谁有问题
全班哪里有问题
这个问题是不是共性
AI有没有误判
```

所以不要做一个页面换个标题复用。

底层数据可复用，信息结构要不同。

---

# 七十二、学生报告首页建议

优先级：

```text
关键问题
↓
本次结果
↓
错误视频
↓
步骤明细
↓
历史趋势
↓
能力表现
```

---

# 七十三、教师班级分析首页建议

优先级：

```text
高频异常
↓
困难步骤
↓
需要关注学生
↓
整体完成情况
↓
AI待复核
↓
成绩分布
```

成绩分布不要放第一位。

---

# 七十四、课堂实时数据与课后统计必须区分

课堂进行中：

```text
实时异常人数
当前步骤分布
长时间停滞
```

这些是动态状态。

课堂结束后：

```text
最终确认异常
成绩
完成率
```

才进入正式统计。

不要把尚未解决的实时状态直接永久写进教学统计。

---

# 七十五、班级报告生成时间

训练任务结束后立即产生初步报告。

如果有待复核：

```text
报告状态：
数据待确认
```

复核完成后：

```text
正式报告
```

考试场景则建议：

> 只有 FINALIZED 后才形成正式成绩报告。

---

# 七十六、统计粒度

系统长期需要至少支持：

```text
Session
Student
Class
Task
SOP
Course
```

但一期前台只重点展示：

```text
Session
Student
Class
```

课程级放 P1。

---

# 七十七、不要一开始做学校级“大数据驾驶舱”

例如：

```text
全校AI实训指数
专业AI赋能指数
```

这类指标一期意义不大。

先保证：

> 一堂课的数据老师真的愿意看。

然后自然向上汇总。

---

# 七十八、一期个人分析必须有

严格压缩：

```text
训练总览

异常
视频证据
标准视频对照
历史训练趋势
基础能力维度
```

---

# 七十九、一期班级分析必须有

严格压缩：

```text
平均用时
高频异常
困难步骤
学生列表
教师介入次数
AI待复核数量
```

# 八十、一期视频证据必须有

严格压缩：

```text
异常时间点
点击异常跳视频

```

多机位、案例库等可以后补。

# 八十一、一期暂缓

暂缓：

```text
AI自动生成长篇学习报告

```

# 八十二、训练报告生成逻辑

Session Finalization 后：

```text

+

+
Feedback
+
Teacher Intervention
+
Assessment
```

聚合生成：

```text

```

页面只是展示这一份结构化数据。

不要每打开一次报告都重新跑 AI。

# 八十三、训练报告对象

建议至少包含：

```text
abilityScores
videoTimeline
teacherComment
```

# 八十四、Learning Behavior

建议单独定义：

```text
LearningBehaviorMetric
```

包括：

```text
standardVideoViews
feedbackCount
retryCount
helpRequestCount
teacherInterventionCount
```

这些不属于评分，却非常有学习价值。

# 八十五、学生一次训练完整数据

例如：

```text
成绩：86

步骤：
12

完成：
11

异常：
3

4

2

查看3次

请求教师：
1次

教师介入：
1次

总时长：
08:42
```

这已经比传统实训记录丰富很多。

---

# 八十六、重复训练真正应该优化什么

学生不是只追求：

```text
分数上升
```

系统希望观察：

```text
错误减少
提示减少
重试减少
教师介入减少
操作更稳定
```

即：

> 从“被指导完成”逐渐变成“独立完成”。

---

# 八十七、独立完成率

可以定义：

```text
未发生系统提示和教师介入情况下完成的步骤
/
全部完成步骤
```

例如：

```text
9 / 12
= 75%
```

这是一个很有潜力的训练指标。

一期可以先存数据，P1 再展示。

---

# 八十八、一次成功率和独立完成率区别

### 一次成功率

看：

> 是否第一次 Attempt 就成功。

### 独立完成率

看：

> 是否没有依赖提示/老师。

两个维度不同。

一个看操作熟练。

一个看训练依赖。

---

# 八十九、班级教学分析示例

一节课结束后，系统可以形成：

```text
机械1班
机械零部件标准装配

参与30人
完成28人
平均成绩82.4
平均用时09:18
```

然后：

```text
本次主要问题

1.
S07 工具选择错误
12人发生
占40%

2.
S10 最终复检遗漏
9人发生
占30%

3.
S04 操作顺序错误
7人发生
占23%
```

再展示：

```text
需要关注

张三
连续3次训练出现S07工具错误

李四
本次4个步骤需要系统重复提示

王五
本次训练未完成
```

这已经具备非常明确的教学价值。

---

# 九十、系统不要替老师写死教学结论

一期不要自动说：

> 建议教师加强工具选择理论教学。

除非后续通过 LLM 做明确标识：

> AI生成建议。

一期先展示事实。

老师完全能够根据：

```text
40%工具错误
```

自行判断。

---

# 九十一、以后 LLM 应该放在哪里

未来大模型最适合基于：

```text
结构化训练数据
```

生成：

```text
个人训练总结
教师班级分析摘要
教学建议
```

而不是直接：

> 把18分钟视频扔给大模型判断整套 SOP。

底层结构化引擎仍然是核心。

---

# 九十二、LLM 输入示例

未来可以给模型：

```json
{
  "student": "匿名学生",
  "score": 86,
  "exceptions": [
    "S07_WRONG_TOOL",
    "S10_STEP_MISSING"
  ],
  "retries": 2,
  "helpRequests": 1,
  "history": [
    68,
    79,
    86
  ]
}
```

让 LLM 输出自然语言。

这比直接理解视频成本低、可控性高。

---

# 九十三、AI生成内容必须和事实数据区分

未来页面可以：

```text
数据事实

成绩：86
错误：2项
用时：08:42
```

下面：

```text
AI训练建议

……
```

不能把 AI 生成结论伪装成正式评分结果。

---

# 九十四、数据闭环

这一模块最终还会反向服务 AI。

例如教师复核发现：

```text
某个错误视频是AI误判
```

直接标记：

```text
False Positive
```

该视频片段进入：

```text
Hard Sample Dataset
```

最终：

```text
训练
↓
模型升级
↓
Event能力提升
```

# 九十五、典型错误样本

系统后期可以自动筛选：

```text
高频误判
教师驳回
AI不确定
低置信度
复杂遮挡
```

形成：

> 模型改进优先样本池。

这样视频不仅服务教学，也服务 AI 持续优化。

# 九十六、两种数据闭环

实际上平台长期有两个闭环。

### 教学闭环

```text

↓
评价
↓
复盘
↓
再次训练
↓
能力提升
```

### AI闭环

```text
AI识别
↓
教师复核
↓

↓
能力提升
```

这是这套平台很有价值的地方。

# 九十七、视频存储成本需要提前考虑

如果：

```text
30个工位
每天6小时
1080P
```

视频量会非常大。

产品不能默认：

> 永久保存所有原始高清视频。

长期需要设计：

```text
保留策略
压缩
冷热存储
关键片段长期保存
```

一期 PoC 可以简单。

但架构必须知道未来这是大成本项。

# 九十八、建议的视频存储策略方向

例如未来可配置：

```text
完整训练视频：
保留90天

异常片段：
保留1年

考试视频：
保留1年或按学校规则

结构化数据：
长期保留
```

实际期限由学校配置。

---

# 九十九、关键片段和完整视频生命周期分开

即使完整视频删除：

```text
错误片段
```

也可以根据规则保留更久。

但如果涉及正式考试完整性要求，则不能随便拆分。

所以：

> 训练和考试需要不同策略。

# 一百、视频删除的审计

如果人工删除：

```text
谁删除
什么时候
什么原因
```

一期可以先实现管理员删除权限。

后期强化审计。


# 一百零二、视频分享

> 后续按权限和有效期做。

# 一百零三、学情分析与传统考试最大的区别

传统考试通常只有：

```text

```

AI-SOP 可以知道：


所以价值不应该停留在：

> 自动评分。

> **过程性技能评价。**

# 一百零四、过程性评价的核心数据

可以归纳为：

```text
结果
过程
效率
错误
纠正
辅助依赖
```

例如：

```text
最终完成了吗？
怎么完成的？
用了多久？
出了什么错？
是否自己纠正？
依赖多少提示？
```

这是传统人工观察很难规模化持续记录的。

---

# 一百零五、一期不要过度包装“能力画像”

能力画像必须建立在真实过程指标上。

正确顺序是：

```text
先积累过程数据
↓
再建立评价指标
↓
再验证指标是否真的反映能力
↓
最后形成画像
```

不要反过来先设计一个漂亮雷达图，再硬找数据填。

---

# 一百零六、最初能力维度应该由专业教师确认

例如：

```text

工具使用
流程规范
操作规范
完成质量
熟练程度
```

真正进入机械专业 PoC 时，要拿：

```text

实训指导书
```

重新确认。

这是普通在线考试系统完全没有的。

# 一百一十二、这个模块的验收标准

一期至少满足：

第一，任何确认异常都可以快速定位到对应视频证据。

第二，任何步骤都可以查看自己的操作片段。

第三，学生可以对照自己的操作和标准视频。

第四，教师可以直接看到全班高频错误，而无需手工统计。

第五，学生多次训练可以看到明显的历史变化。

第六，教师复核结果会同步更新成绩和学情统计。

第七，AI误判不会污染最终班级教学统计。

第八，视频、步骤、异常、成绩之间的关系完整可追溯。

# 一百一十三、这一层最终形成的核心资产



### 第三类：AI困难样本数据

```text

不同操作习惯

```

这三类数据结合起来，才是这个平台长期真正有价值的资产。

# 一百一十五、一句话定义视频证据链

> **视频证据链不是保存录像，而是让系统中的每一个步骤结果、异常判断和评分结果，都能够准确回到真实操作发生的时间、画面和判定依据。**

---

# 一百一十六、一句话定义训练复盘

> **训练复盘不是让学生重新看完整录像，而是把一次十几分钟的实训自动压缩成若干值得回看的步骤、错误和关键操作片段。**

---

# 一百一十七、一句话定义学情分析

> **学情分析不是把成绩做成图表，而是利用 AI 持续采集的过程数据，帮助教师发现“谁在哪里反复出错、全班哪些步骤最难、哪些能力需要重新教学”。**

这三者结合之后，AI-SOP 才从“自动识别和自动评分工具”进一步变成真正有长期教学价值的实训数据平台。
