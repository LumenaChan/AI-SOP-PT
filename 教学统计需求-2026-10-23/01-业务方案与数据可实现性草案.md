# 教师端教学统计：业务方案与数据可实现性草案

日期：2026-10-23。状态：业务方案已获用户“方案没问题，继续”确认；包含当前筛选明细导出。功能方案待确认，原型尚未开始修改。

本文件保留首轮建议及待确认用语作为过程记录。后续功能定义见[完整功能方案草案](02-完整功能方案草案.md)，其业务细化仍待本轮确认，不据此授权开发。

## 1. 已确认内容与本轮目标

已确认的方向：教师端新增一个一级菜单“教学统计”，菜单内含“班级成绩、学生进步、步骤分析、教学跟进”四个页签。教师工作台已移除统计范围筛选卡片，保留简要指标和现有明细/办理入口。

当前系统已能安排实训、逐步操作、形成结果、办理求助、复核、补证和辅导；但分析集中在首页少量指标，缺少跨安排查看班级和学生表现的入口。本期需要使教师能够从统计发现问题、查看具体依据、进入现有流程处理，再回来看更新后的结果。

本文件先对齐业务范围、数据能力和规则建议。下一步再整理功能清单与页面方案；三者确认后形成用于原型修改的概念版需求。它不是按已完成页面反写的正式落地PRD。

## 2. 建议的一期范围

| 内容 | 建议提供的业务能力 | 具体价值 |
| --- | --- | --- |
| 班级成绩 | 班级内有效结果汇总、成绩分布、参加/未参加记录、学生结果明细与源报告 | 了解本次或一段时间内的整体表现，找到需核对的记录 |
| 学生进步 | 学生在同一SOP版本、同一结果类型中的历次有效成绩、首末变化、步骤对比 | 识别多次练习中的变化，保留每次原始依据 |
| 步骤分析 | 同一标准下步骤成绩、已确认扣分频次、证据来源及学生明细 | 确定哪些操作需要重点讲解，并区分扣分与缺证 |
| 教学跟进 | 求助、补证/补测、辅导的状态分布与办理记录；复核、流程确认、待发布的现存工作量 | 了解教学问题是否有人跟进，进入既有详情继续办理 |
| 共用查询 | 当前教师数据范围，班级、课程、SOP/版本、练习/考试、日期筛选，样本与排除原因、数据明细 | 保证图表、数字和来源能互相核对 |
| 当前明细导出 | 建议纳入：导出当前筛选下的明细及统计口径，体现导出时间和成绩版本 | 支持教师复盘及留存当前分析结果 |

“当前明细导出”是本次待确认建议；尚未实现，不承诺已有历史导出可重现原文件。若首期希望更集中，可将导出单独后置。

一期不新增：AI自动诊断/自动写学生评语、能力画像、技能掌握率、教师绩效排名、全校管理报表、自动排课、校务系统对接、任意拖拽报表设计、历史时点状态回放。也不借此实施原审查中暂缓的其他事项。

不新增任务状态机：求助、补证、辅导继续使用已经存在的对象和办理流程；统计页不得用“标记已处理”按钮绕过原有核验。

## 3. 角色、数据范围与主流程

### 3.1 谁使用、谁处理

- 教师查看自己负责的安排与相应学生结果，不因学生与他有其他课程关系就开放其他教师的结果。
- 统计页以查看、筛选、对比和定位为主。需要改分、确认补测、办理求助时进入原有业务页面，由原责任教师处理。
- 低分结果可按既有规则发起辅导，必须保留来源成绩和责任人，并防止相同目标的未结任务重复创建。
- 学生继续只访问自己的任务、回执和允许查看的结果；不新增学生访问教师统计页的权限。
- 管理员本次不新增独立统计入口。生产环境的真实身份/组织权限仍需后续接入；当前原型沿用已有演示教师身份，不能宣传为真实认证。

### 3.2 端到端流程

进入教学统计 → 选择范围和页签 → 查看汇总及样本数 → 点击学生/步骤/任务 → 查看来源记录 → 按权限进入既有报告或办理页 → 保存成功 → 返回原统计条件 → 根据当前数据重算。

关键分支：

1. 无数据：显示真实空态；不自动改日期、恢复已删除样例或补虚构统计。
2. 成绩待复核/任务未结：展示对应状态和办理入口，不作为正式成绩样本。
3. 缺少历史日期或归属：标明“未记录”，不编造；具体筛选无法判断匹配时单列排除原因。
4. 来源被删除、取消、权限改变：入口显示关联失效/不可访问，允许回到统计；不跳到别人的Session代替。
5. 保存失败：任务/成绩保持原状态，统计不先展示成功；说明和当前查询条件尽量保留。
6. 同源数据更新：按最新已保存事实刷新；回到原页签及筛选条件，成绩修订后不得把同一Session当新的一次练习。

## 4. 四部分的业务边界与指标建议

### 4.1 班级成绩

建议先显示：有结果的学生人数、有效正式结果人次、平均得分、成绩区间分布、待核对/待复核记录；参加情况单独展示。

- 平均分与首页保持同一口径：按有效正式结果人次计算。重复练习计多个人次，但“有结果的学生人数”按学生去重。
- 分母不同必须写清：平均分的样本是有效结果，参与情况的分母是所选安排的实际应参加分配，不是班级当前总人数。
- 每次成绩统一换算为百分制，仍能看到原分/满分。不同SOP的平均分仅为汇总概览，不用于判断同等难度或直接排名。
- 班级横向对比建议限定同一SOP及版本、同一练习/考试类型；样本数和重复次数同时展示，避免练习次数不同被解释成教学优劣。
- “未参加”按明确的记录状态统计；缺少Session不直接判缺考，显示记录待核对。
- 及格率建议首期采用固定百分制60分作为展示阈值，并明确标注；这是产品建议，尚未确认学校正式考核规则。不能把辅导阈值80分当作及格线。

### 4.2 学生进步

建议提供学生选择、历次结果时间序列、首末得分变化、步骤对比及关联辅导记录。

- 比较单元是“学生 + SOP身份 + 明确记录的版本 + 练习/考试类型”。课程相同不代表评价标准相同。
- 同一单元有至少两次有效、可确认先后顺序的结果，才显示变化值。一次结果显示“尚不足以比较”；没有有效结果显示“暂无有效结果”。
- 变化值为末次百分制得分减首次百分制得分，单位写“分/百分点”，不写模糊的“提升百分比”。负数如实展示。
- 默认用所选日期范围内首末结果；若要比较区间外基线，需另作显式选择，不能悄悄引入范围外数据。
- SOP版本未记录的旧结果可查看，但不能仅因都写“版本未记录”就认为可比较；同名不同SOP也不能合并。
- 多条结果时间无法区分时，不靠ID猜测哪次是后测；展示来源并说明无法可靠计算首末变化。
- 改分更新同一条结果的当前有效版本，不增加练习次数。默认分析当前有效分，不声称还原历史某日看到的成绩。
- 分数变化与证据来源同时展示；保分、人工确认、真实AI证据与演示证据分开，不把满分直接称为掌握技能。

### 4.3 步骤分析

建议提供同SOP版本下的步骤对比、平均得分、已确认扣分记录数及来源。

- 每一个有效Session的同一步骤最多计一条扣分记录；多次修订或多条观察事件不能重复累计为多个错误。
- 步骤汇总键包含SOP身份、记录版本、Step ID；名称只用于显示。
- 复用既有高频错误的确认来源规则，普通结束会话审计不等于教师确认错误。
- 如展示扣分记录占比，分母为当前范围内该步骤有有效成绩的结果人次，分子为其中符合确认规则且当前仍有扣分的人次；不是识别准确率。
- 取消扣分后，统计随当前有效成绩变化；原修订依据仍在报告中可查。
- 待复核、未操作、未结束、无效分排除，并解释数量；只有缺证/遮挡或按规则保分不得计为学生错误。
- 建议将“成绩情况”和“证据情况”并列说明，避免把无扣分记录解释为自动识别全通过。

### 4.4 教学跟进

建议按业务类型分组看数量和状态；不把不同单位混成一个“完成率”。

| 类型 | 统计单位 | 主要状态 | 正式办理落点 |
| --- | --- | --- | --- |
| 学生求助 | 求助记录ID | 待接手、处理中、已完成、已撤销、随会话关闭 | 原Session工位求助办理区 |
| 补证/线下补测 | 任务ID | 待办理、办理中、待教师确认、已完成、已取消 | 原补证/补测任务详情 |
| 学生辅导 | 任务ID及涉及学生去重人数 | 待安排、辅导中、待复查、已完成、已取消 | 原辅导任务详情 |
| 成绩复核 | 当前需处理的Session/步骤 | 当前仍待复核或处置 | 精确Session/步骤的个人报告 |
| 人工流程确认 | 当前确认请求 | 等待教师确认 | 原工位当前确认区 |
| 考试发布 | 符合条件的考试安排及结果份数 | 待发布、待复核、已发布 | 原考试结果页 |

- 前三类有稳定历史对象，可在记录完整时统计创建和完成情况；后三类首期侧重当前工作量与来源，不承诺完整历史工单趋势。
- “已撤销”“已取消”“随会话关闭”单列，不冒充教师完成或问题已解决。
- 如展示完成率，建议只针对具体类型：当前查询内成功完成任务数 ÷ 非取消/撤销的有效任务数；自动关闭与未知状态单列，不并入成功完成。各类型最终分母在功能方案中再逐项锁定。
- 求助/补证/辅导的日期筛选建议按创建时间选取任务，展示它们现在的状态；不是“在这个日期范围内办结”的另一种口径。复核、流程确认、考试发布的当前工作量不套任务创建日期，必须显示当前状态并分别说明来源范围。
- 无完整接手、完成时间的旧记录不计算平均响应时长。首期不将响应/处理时长列为核心考核指标。
- 辅导办结只减少未结任务，不修改学生历史分数；学生最新结果仍低分时继续如实显示。

## 5. 共用统计约束

1. 查询范围：当前教师、班级、课程、SOP/版本、练习/考试、日期。默认建议保留原型全部记录，避免按真实日期清空样例；一旦设置日期，显示时间依据与排除数量。
2. 成绩时间优先实际结果形成时间。建议实际完成/交卷时间不足时单列“结果日期未记录”；不能拿计划开始时间伪装为实际成绩日期。现有首页有计划时间兜底，新模块实施前需决定是否同步首页，该差异不能静默保留。
3. 任务日期采用该类型的业务时间，切换到教学跟进时明确提示日期含义不同；不能用成绩完成日期过滤辅导的创建情况。
4. 正式有效分复用已修复的校验：null/空值/非法/越界不计有效成绩；合法0分有效；满分依据缺失不能擅自补100。
5. 教师可分析本人未发布考试的核定结果，但学生与公共大屏仍按原保密规则；统计入口不扩大学生可见字段。
6. 成绩按当前有效版本重算；分数/状态修改后，汇总、图表、明细、源报告保持一致。统计自身不触发改分或补分。
7. 0、无记录、被排除、权限不足、历史未知分别展示。分母为0时显示“暂无可统计结果”，不显示误导的0%。
8. 班级归属优先历史Session/安排的已记录信息。仅有当前学生班级时必须标明来源，不能宣称是历史班级快照；未知归属单列，不能补到任意班。
9. 课程名为旧数据的唯一课程依据时标明历史记录口径；没有课程标识时不因同名自动建立跨SOP的可比关系。
10. 当前明细导出若纳入本期，必须与当前范围/页签一致，包含样本单位、排除说明、生成时间、成绩版本；多页数据应说明导出全部符合条件记录还是当前页。建议导出全部符合条件记录，不扩大到未授权教师范围。
11. 数据来源切换继续保留浏览器工作数据与CPD各自独立；同源刷新不恢复已处理/删除的演示任务，新增示例不得混成真实算法验证结果。
12. R03“多补证任务全部取消后仍待复核”仍是已知暂缓问题。新统计必须如实显示当前待复核，不在统计页偷偷清除状态或默认为正式成绩；是否另行修复需用户授权。

## 6. 现有数据能否支撑

本轮只读核对了当前CPD与共享规则，未读取当前浏览器工作数据，以下数量仅用于判断覆盖情况，不作为未来页面的固定数。

CPD包含44个安排、6名学生、3个班级、6个补证任务、4个辅导任务。当前演示教师范围共有44条Session来源行，其中26条为有效正式结果。部分学生有同SOP版本的多次有效练习，能支持真实的多次记录示例；不同学生/版本的覆盖不均衡。

| 能力 | 现有依据 | 可实现性与补齐要求 |
| --- | --- | --- |
| 有效成绩/均值/发布率 | teacherDashboardMetrics、gradeScoreValidityRules | 可以复用，不另造一套分数规则 |
| 班级成绩 | 学生、安排、Session与班级关联 | 可做当前记录汇总；历史归属来源需明确，不能承诺任意历史时点重建 |
| 学生多次成绩 | 稳定studentId/Session、SOP身份/版本、结果分与时间 | 可做已知标准和顺序的比较；版本/时间缺失时降级为历史查看 |
| 步骤扣分分析 | Session步骤、当前有效分、教师修订/确认来源 | 可复用已确认扣分规则；新增分母和来源说明 |
| 求助/补证/辅导状态 | helpRequests、evidenceTasks、supportTasks及历史 | 可做状态分组和当前结果；旧时间不全时不补造时长 |
| 待复核/待确认/待发布 | teacherDashboardTasks及原办理页面 | 可显示当前来源列表；不能直接当作完整历史工单库 |
| 当前明细导出 | 统计读取结果 | 如确认纳入，需新增即时导出功能；不能沿用“历史文件可完整恢复”的假设 |
| 全校排名/教师绩效 | 尚缺真实组织与授权，以及可比教学样本 | 本期不做 |
| AI准确率/技能掌握率 | 没有独立真值集与现场评测依据 | 本期不提供 |

演示数据建议在实现时按确认范围补齐：同一标准下两班对比、同一学生至少三次有明确日期的练习、保分与确认扣分并存、待复核排除、无数据、仅一次结果、版本变更、各类任务终态。通过共享幂等工厂追加关联数据，保留现有成绩和快照，不在统计页写固定数字。

## 7. 本轮建议确认的业务方案

建议采用：

- 一个一级菜单、四个页签；工作台保持简洁。
- 一期四个方向都覆盖基本汇总、来源明细和既有流程联动，避免只做图表。
- 先做教师本人数据，复用既有成绩/任务对象；不扩成全校BI和AI诊断。
- 平均分按有效结果人次，与首页一致；学生进步按同SOP明确版本、同结果类型比较。
- 建议附带当前筛选明细导出；不做归档报表和旧文件恢复。
- 及格展示阈值暂建议60分；辅导触发沿用80分，两者明确区分。学校另有规则时在功能方案中调整。

待确认的关键范围：是否将“当前筛选明细导出”纳入首期；是否接受上述四部分及基本指标边界。及格线、跨页返回保留条件等随后在功能/页面方案中细化，不视为已经开发批准。

业务方案确认后，再分别给出完整功能草案和逐页方案。当前文件不包含未确认的最终功能编号和页面清单，避免把建议直接当成已定方案。

## 8. 依据与本轮自检

依据：当前对话关于一级菜单和四页签的裁定；现有DashboardPerformancePanels、teacherDashboardMetrics、gradeScoreValidityRules、teacherDashboardTasks、sessionClosureRules、evidenceTaskRules、supportTaskRules、studentResultRules；AGENTS中数据源、保分、考试保密、已暂缓问题等约束。

自检：已区分确认内容/建议内容；核对现有字段与可计算性；区分人/人次/任务；补充时间与历史口径；保留已有状态机和权限边界；图表指标均须能定位来源；未新增AI能力；未把R03或其他暂缓问题纳入实施。只新增需求草案，不修改原型或业务数据。
