# 数据采集与算法验证方案

日期：2026-10-15。目标：在固定工作台上验证可见 SOP 过程检测及预标注收益，再决定是否扩展。

本文件定义拟议试验，不包含已跑出的模型结果。任务具体操作要求由课程教师确认，时间阈值、工具规格和测点顺序不能由模型编造。

## 1. 首试任务卡

### 1.1 手套佩戴完成状态

| 项目 | 试验定义 |
| --- | --- |
| 主要目标 | 判断当前学生双手是否处于教师要求的佩戴状态 |
| 可见输入 | 固定工作台近景，左右手与手套清楚可见 |
| 可接受变化 | 教师允许的左右手先后、佩戴速度、整理方式；若只考核状态，提前戴好也可接受 |
| 正例 | 可见双手均戴好，达到教师规定的持续条件 |
| 负例 | 桌上两只、手持两只、只戴一只、仅套入部分但未达到教师标准、戴好后脱掉 |
| 不可判定 | 一只手隐藏、手套/手关系看不清、人物归属不明、证据区间断流 |
| 明确不判断 | 手套真实绝缘性能、内部破损等画面不能确认的性质 |
| 输出 | 双手佩戴/单手/未佩戴等可见状态候选，或者未知；证据、时间与状态变化 |
| 规则 | 业务规则检查状态、持续和适用作业区间；未知不扣分，不伪造已完成 |

课程若考核穿戴过程，另录和标取用、穿入、整理等子动作。不能在“只要求戴好”的任务中把先戴左还是右当作错序。

### 1.2 表笔检测可见过程

| 项目 | 试验定义 |
| --- | --- |
| 主要目标 | 在一种固定工件和工具上判断教师规定的可见检测动作与对象关系 |
| 可见输入 | 工具、两支表笔、规定工件/测点及操作手在画面中有可核对证据 |
| 正例 | 完成教师规定的操作和顺序，表笔到达规定测点并形成可见有效动作证据 |
| 合法变化 | 左右手拿法、允许的移动路线/速度、合理停顿 |
| 负例 | 只拿仪表、仅在附近晃动、表笔悬空、错工件/错点、仅单侧到达、开始后中断、漏子动作、错序 |
| 不可判定 | 接触位置被遮挡、无法分辨到达/接触、工具尖端过小、关键区间缺失 |
| 明确不判断 | 测量数值、电气测量有效性或实际接触电阻；本试验仅覆盖画面能支持的过程 |
| 输出 | 操作动作候选、对象/测点关系候选、子动作起止与完整性；证据与未知原因 |
| 规则 | 根据教师要求组合动作、对象和时间；表笔靠近不能直接认定有效接触 |

若普通机位无法区分“悬空”和“到达规定点”，先调整拍摄/任务边界，不能用模型高置信文本替代接触证据。

## 2. 采样矩阵与数据结构

### 2.1 覆盖矩阵

| 维度 | 首轮必须覆盖 | 后续针对失败补采 |
| --- | --- | --- |
| 人员 | 教师与多名学生，不只一个人的重复动作 | 未见手型、身高、衣着、操作习惯 |
| 合法变化 | 左右手、正常快慢、自然停顿 | 特殊但符合标准的拿法/姿态 |
| 错误与伪完成 | 每个任务卡明确的主要负例 | 被错判为完成的困难负例 |
| 过程 | 完整、真实中断、重复、错误后纠正 | 多次尝试及长时间间隔 |
| 场景 | 固定机位正常照明、普通桌面背景 | 已声明允许的照明/摆放变化 |
| 可见性 | 清楚、部分遮挡、关键部位不可见 | 工具遮手、手挡测点等高频问题 |
| 无动作 | 空闲、整理物品、拿取无关工具 | 容易触发目标动作的背景行为 |
| 运行异常 | 缺帧、短时断流、恢复 | 长时间运行、资源积压与录像缺口 |

负例使用安全道具、脱能训练设备与教师安排的模拟动作。不以危险行为作为采样方式。

### 2.2 初始规模与扩充方式

可按“2名教师＋约6名学生，每个任务每人先做约5次正确/合法变化，再补主要负例和不可判定场景”启动探索。这个量级只用于发现管线问题和估算学习难度，不是生产错误率验收样本。

保留完整演练录像，同时派生动作片段和用于对象/关系标注的关键帧。独立单位是参与者、完整演练或真实动作事件，不是相邻帧或大量重叠窗口。

第一轮跑通后，按最严重错误类型追加样本，画出增加训练数据后的独立验证趋势。达不到目标时先归因，不能只盲目增加同一教师的重复演示。

### 2.3 素材索引

每条原始录像记录：匿名参与者、角色、演练/组ID、任务、日期、场景、工具/工件版本、相机配置、实际帧率/码率、光照、完整录像位置、用途、记录人。派生数据继承组和版本。

片段记录：源视频、起止时间、动作类型、完整性、正确性、允许变化、错误类型、可见性、对象关系和人工标注记录。能力库不展示具体SOP；教师要求映射与专家判定放独立评测清单及AI能力配置。图像框/关键帧与片段双向关联。

原型数据不能冒充真实采集素材。真实模型请求不得读取只有 `mock-frame://` 等引用的样本；真实文件可访问性和时间区间必须验证。

## 3. 划分、标注与专家一致性

### 3.1 三个用途

- 开发训练：训练模型或选择参考样本，可看标签和错误。
- 验证调优：选择窗口、阈值、候选模型与规则；和训练Session隔离，尽可能留出参与者。
- 封存测试：独立学生与演练，方法和参数固定后评测；不得反复据此选参数。

首轮可以先留下部分学生作为未见参与者测试，具体人数视现场安排；最终统计验收需要额外独立样本。测试错误一旦进入调优，就不再是封存测试证据，应建立新的独立测试。

同一演练的全部片段、帧、同步录像归同一组。随机打散图片或把同一个动作的窗口分在不同集合，不能证明学生泛化能力。

### 3.2 金标准

至少两位教师对关键测试事件独立判断，保留分歧并形成统一裁定。先固定以下判定：符合要求、已知错误、真实未完成、不可判定。

动作类别、正确性、完整性、可见性分开。Other/背景不是万能负例；不可见样本不能强标“未做”或“无目标”。

对象/关系关键帧用于需要精细判断的要求，不要求所有帧都打骨架。若关系无法从画面确认，标准答案也应允许不可判定。

动作起止点按任务定义：开始操作与拿工具准备是否区分、结束动作与状态保持是否区分。判断次序使用教师要求的业务事件，不让标注员按外形猜步骤。

### 3.3 清洗的具体底线

文件损坏或错误裁剪需要修复/重新切片；真实操作只做一半是有效负例；遮挡素材可用于未知与鲁棒性验证。清洗结果与后续用途都保留。错误操作不因为“错误”而剔除。

## 4. 算法试验顺序

### 4.1 建立三类基线

| 基线 | 输入/输出 | 能回答的问题 |
| --- | --- | --- |
| 对象与状态基线 | 工具/手/手套/工件区域，局部佩戴状态 | 是否必须学习完整穿戴动作；对象/关系能否可靠辨认 |
| RGB短动作基线 | 工作区局部连续视频 → 目标动作/背景候选 | 不使用骨架能否在未见学生上识别目标动作 |
| 动作＋对象＋规则基线 | 动作候选、位置/关系、持续条件 → 要求结果 | 是否比单一动作分类器更能拒绝伪完成 |

采用预训练模型适配，首期不从几段示范从零训练视觉模型。具体模型由算法人员依据部署、许可、资源及试验选择；不能把通用数据集上的准确率当作业务效果。

可研究参考匹配/少样本作为对照，但偏离教师样式只产生疑似异常，不能直接作为扣分依据。

### 4.2 再决定手部关键点

只有无骨架基线出现“运动或姿态表达不足”的主要错误时，增加自动提取手部关键点的实验，并与同一数据/评测对照。

检查戴手套、手持工具、双手交叉情况下的关键点有效率、轨迹稳定性、推理负载和未知率。若需要重新训练关键点检测器，再针对性人工打点；不先做全量手工骨架。

若加骨架未改善错误完成或净工作量，不进入首期生产。不能因骨架图更直观就宣称算法更可靠。

### 4.3 连续视频阶段

完整视频按任务需要保留时间上下文，持续产生窗口候选。窗口长度/采样密度由动作速度及完整性试验决定，不写一个对所有几秒动作都适用的固定帧数。

聚合过程要区分动作开始、进行、结束/中断和背景；合并重叠窗口的一次动作，识别重复尝试；用明确观察持续时间，不复制配置的最短时长作为已观察时长。

记录事实不限定当前步骤，业务层再决定适用窗口。手套等状态在指定区间继续更新；离开视野变未知，不能永久继承以前的佩戴结论。

未知处理分三处验证：画质/可见性不足、人物/对象关联不明、动作证据不足或不在已验证范围。训练背景类不能保证自动识别所有未见动作；模型分数阈值由独立验证选择，并检查未见负例、拒判与误接受的代价，不能把一个高分直接解释为正确概率。分类器总能给出最高类别，不代表该类别已经成立。

离线整段评测通过后接真实视频流，测试解码、队列、延迟、证据索引和断流。模型批量推理能运行，不等于多路现场并发已通过。

## 5. 预标注对照试验

对象任务比较：纯人工、现有检测预标注、Seek或其他开放词汇定位预标注；需要时增加经校正关键帧的区域传播。动作片段定位另做对照，不把两类收益合并成一个自动化率。

1. 从开发数据抽取难度相近且互不重复的批次；采用交叉分配，减少标注员能力和第二次看同一素材的记忆影响。
2. 先固定质量标准和审核方法，再记录耗时；人工测试金标准独立于正在比较的自动标签。
3. 记录框/类别错误、漏标、动作起止误差、返工、抽检和任务管理。
4. 同质量完成后再比较人时；机器时长、显存、费用与管理负担单列。
5. 长尾小工具、桌上/手上关系、无目标建议分别统计，不能只用简单正例证明节省。

计算：`净节省比例 = 1 - 预标注方案全部人工人时 / 纯人工方案全部人工人时`。

若净节省不足、复杂维护抵消收益，保持人工或选择更简单管线。预标注结论与实时识别结论分开决策，任一失败不自动否定另一条路径。

## 6. 评测定义与统计单位

| 指标 | 计算与含义 |
| --- | --- |
| 错误完成率 | 被系统宣告自动完成但专家不认可的独立事件数 / 系统宣告自动完成的独立事件数 |
| 负例误接受率 | 被错误接受的已知负例事件数 / 全部对应负例事件数，按错误类型拆分 |
| 正确事件召回 | 被系统正确识别并归属的有效事件数 / 专家标定有效事件数；时间/类别/要求匹配条件在评测前锁定 |
| 可判定率 | 在声明可自动任务内给出有足够证据的判定的要求实例数 / 全部该范围要求实例数；未知与系统缺失分别列出 |
| 未知正确性 | 真正不可判定时是否返回未知，以及可见有效动作被不必要拒判的情况 |
| 事件重复/归属 | 一次操作产生多次事件、错人物/错要求的次数 |
| 边界误差 | 起止相对专家边界的误差与漏掉关键子动作情况；允许误差由任务事先定义 |
| 连续背景误报 | 每小时无目标操作录像中的误报次数，与事件级错误同时报告 |
| 延迟 | 采集到候选、教师条件满足到规则确认、确认到页面反馈分别记录P50/P95；动作本身所需等待单列 |
| 业务价值 | 每Session教师复核时间、证据寻找时间、误报处置时间、人工改判和净节省 |
| 资源 | 峰值显存、解码负载、队列长度、丢帧/证据缺失、持续运行温度与恢复 |

“全部要求”的自动覆盖和“已选自动要求内”的可判定率分别报告。不能因为删除困难要求就宣称全部SOP覆盖率上升。

对出现次数和顺序要求，验证正确事件计数和时序；帧级分类准确率只作为诊断。安全候选按场景漏报和误报/小时独立统计。

## 7. 试点门槛和统计证据

建议目标沿用文档01的候选口径：预标注净人时节省约30%；自动完成错误率低于1%，且可判定率/正确事件召回候选不低于90%。试验启动前由负责人锁定范围与具体要求。它们不是已有结果，也不是高压安全认证。

不同分母独立报告样本量、置信区间和错误类型。若100个自动完成事件零错误，单侧95%错误率上界近似仍为3%；300个零错误才约为1%。并非收集300个相邻窗口即可证明1%目标。不能从300个负例零误接受推导所有输出的错误完成率；两项是不同分母。[统计说明](https://pmc.ncbi.nlm.nih.gov/articles/PMC2550668/)。

探索样本不够时可保持辅助范围，继续累计独立结果。不要在尚无足够证据时签署生产准确率承诺。

## 8. 错误归因与补采闭环

每个严重错误保存：原视频、事件区间、专家结论、预测、对象/关键点/窗口中间结果、版本和资源情况。按以下原因处理：

| 原因 | 后续行动 |
| --- | --- |
| 看不清 | 改相机/照明/工作区；更新采集配置并重新验证 |
| 对象漏检/混淆 | 补小工具、手持/桌面、外观近似负例；检查候选框召回 |
| 动作混淆 | 补相似无效动作、未见人和速度；检查局部裁剪与时间上下文 |
| 关系不足 | 增加对象关系关键帧或专用状态能力；不可见就改为未知 |
| 时间聚合 | 修复重复、边界、中断/恢复逻辑；整段回归 |
| SOP歧义 | 教师澄清草稿；已发布标准需修改则复制创建新SOP，标注按新定义重新确认，不让算法猜 |
| 系统 | 修复取流、时间戳、资源与证据持久化；评价结果按缺失处理 |

从封存测试发现的问题可以指导下一轮，但相应样本转为开发，新的发布评测使用新的封存集。全流程内部记录数据快照和模型文件/任务标识，不新增面向教师的版本管理。

## 9. 现场试点操作

1. **旁路期**：真实模型只记录事件与证据，不参与正式自动评分或完成；已有教师流程照常。原型演示与真实旁路结果分开。
2. **辅助期**：教师查看候选、未知与证据，记录是否有用、是否误报、复核耗时；保分规则不变。
3. **有限自动期**：只开放通过离线与现场验证的判断项；其他要求保持辅助/教师评价。锁定模型/配置，不在考试中热切换。
4. **回退**：错误或故障达到约定停止条件时，关闭受影响自动判断项，保留录像与审计；已确认安全事件仍需处置。

每一阶段以证据和课程负责人认可的适用范围推进，不按演示完成或日历自动升级。

## 10. 验证报告固定结构

报告必须包含：任务与适用边界、输入/算法版本、参与者和划分、金标准及分歧、完整视频数量、事件分母、负例/未知覆盖、分类与事件指标、主要失败、延迟与资源、标注/教师人时、开放范围、人工项、回退条件及后续补采。

附可回放案例：未见学生的正确操作、合法变体、伪完成拒绝、真实未完成、未知、错误后纠正、断流恢复。模型更换必须重跑冻结的开发回归集和新的独立发布评测，不能只展示最好的一条录像。

## 11. 大场景进入条件

固定工作台闭环成立后，按入口/工作台、车周、驾驶舱、车底逐区域新增任务卡和观测图。先验证身份和证据交接，再验证具体操作。现场拍摄覆盖、不同相机负载、车辆位置与举升状态影响都需重新测。

首次扩展以一个实训单元试拍为起点，不默认将5—7个视角作为采购标准。新增区域失败时保留已经验证的工作台能力，并明确大场景中的人工边界。
