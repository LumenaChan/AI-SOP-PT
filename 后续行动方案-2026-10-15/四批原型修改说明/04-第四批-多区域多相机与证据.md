# 第四批修改说明：多区域、多相机与证据

日期：2026-10-15。状态：原型改造已实施；实际覆盖、验证结果和生产接入边界见[实施台账](05-实施台账与演示入口.md)。依赖[共同约束](00-共同约束、影响清单与数据保护.md)和第三批事件/用途；本批实现大场景的产品表达、数据兼容与演示，不宣称实现真实跨镜头识别算法。

## 1. 目标与边界

将一个工位表达为一个实训单元，可含入口、工作台、车周、驾驶舱和车底。相机、区域、判断项、人物归属与证据可明确关联；单视角原流程仍可简洁使用。

到达区域、经过车周与完成具体检查分别表达。轨迹不能自动代表检查质量，驾驶舱/车底不可见时返回未知，不能根据进入/停留推导动作合格。

本批不增加自动转动相机、机器人、地面3D建图、任意多边形ROI或真实多流同步推理；相机数量不预设为固定采购标准。仍采用现有矩形逻辑区域映射，必要技术作为未来接口。

## 2. 已查到的限制与影响矩阵

当前`normalizeWorkstationAiBaseConfig`主要保留primaryCameraId/fallbackCameraId；`allowedCameraIds`只读这两个；判断项绑定一个cameraId；区域编辑主要按logicalAreaId查单条。多区域不能只改工位表单而保留这些读取逻辑。

| 影响对象 | 必改/必查入口 |
| --- | --- |
| 物理设备与工位 | AdminDetail工位、设备创建/编辑/绑定/释放/停用、Provider关系更新、同一设备占用保护 |
| AI基础配置 | `workstationAiRules.js`的归一化、校验、就绪与关键变更比较 |
| SOP工位配置 | `sopWorkstationAiRules.js`的allowedCameraIds、绑定、区域、检查、场景覆盖、失效 |
| AI详情两模式 | AiAreaMappingEditor、AiWorkstationConfigWorkspace、Tab/瀑布中的工位启用部分 |
| 门槛与快照 | `aiEntry.js`、`deriveAiRuntimeGate`、`createAiEvaluationSnapshot`、安排首次开放和刷新 |
| 运行身份/事实 | 两runtime store与Provider、相机局部Track、身份交接、持续状态/事件 |
| 视频消费 | 准备页、学生主视角、教师总览/单人、报告/复核、管理员录像/记录、大屏预览 |
| 数据与测试 | CPD/seed/normalize、新建工厂、source-group、现有单/双相机夹具、跨源迁移 |

必须全文检索primaryCameraId/fallbackCameraId、cameraId、logicalAreaMappings、judgementCameraBindings、trackId、evidenceSources，检查每个读写点。不能依赖旧字段永远自动同步。

## 3. 新配置结构及兼容

### 3.1 相机集合

每个工位维护当前相机集合：设备ID、视角名称、角色、观测区域、启用、默认预览。设备在线/流状态从设备集合读取，不复制一套容易过期的设备状态。

| 角色 | 含义 | 处理 |
| --- | --- | --- |
| 主采集 | 主要预览和观察来源 | 至少一个默认主视角，默认预览只能有一个 |
| 辅助采集 | 同时承担局部证据 | 依判断项确定是否必需 |
| 备用 | 需要按已验证替换方案才使用 | 不自动视为已实现同步融合/无缝切换 |
| 历史第二视角、角色待确认 | 旧fallback实际可能被当辅助使用 | 保留既有ID和显式绑定，提示实施确认，不强改为已验证并发辅助 |

旧primary映射主视角；旧fallback优先作为待确认历史第二视角，不能删掉旧判断项绑定。新集合与旧字段通过集中适配读写：旧字段只作兼容别名，所有业务消费者使用共享相机选择器；默认镜头改变同步旧别名，不能形成两套互相覆盖的真源。

### 3.2 区域与映射

物理工位区域可记录名称和用途；SOP逻辑区域仍归AI配置，具体矩形在相机画面上设置。工位管理不接管SOP判断逻辑。

同一SOP逻辑区域可在多台相机有映射，每条映射以逻辑区域＋相机标识唯一。修改一台相机矩形不能过滤掉另一个视角的同名区域。

界面矩形百分比沿用现有单位；输出像素/归一化由共享适配转换，并记录源分辨率/裁剪条件。调整机位、裁剪或实际输入条件后，相关ROI待重新验证，不凭矩形数值未变就认有效。

### 3.3 判断项视角策略

| 策略 | 最小定义 | 失败处理 |
| --- | --- | --- |
| 单视角 | 选择一台有效相机 | 该视角缺失则该要求未知/按政策降级 |
| 任一视角 | 指定集合，任一提供完整可靠证据即可 | 无一满足为未知；不能把不同人的部分事实拼成完成 |
| 多视角共同满足 | 为不同证据条件指定相机，明确同一人/对象及允许时间关系 | 缺必需条件或归属不明则未知 |
| 按区域顺序 | 教师已有过程要求映射区域事件顺序 | 到达顺序不能代替区域内检查动作 |

首期界面只开放已实现的确定性策略。不可表达/尚无算法的复杂融合可以保存为待实现说明，不能通过配置检查宣称真实可用。

旧单cameraId绑定无损变成单视角记录。读取历史快照仍识别旧字段，不能因为新cameraIds空数组就把旧绑定判空。

## 4. 工位与设备页面

### 4.1 工位详情

有效路由`/admin/workstations/:id`。沿用基本信息/设备/AI基础配置，新增视角列表和区域说明。单主镜头默认收起高级列表，避免所有普通工作台变成复杂大场景表单。

| 控件 | 校验与保存 |
| --- | --- |
| 添加相机 | 仅选当前工位合法相机设备，不允许重复ID、跨工位抢占 |
| 视角名称/角色 | 名称可辨认；默认预览唯一；历史角色待确认有提示 |
| 覆盖区域 | 从当前工位区域选择，不自动生成SOP逻辑区 |
| 主预览选择 | 保存后同步所有预览选择器，旧历史证据仍指原相机 |
| 移除/停用 | 展示依赖的AI配置、判断项及活动会话；有活动依赖时阻止静默释放 |
| 保存配置 | 防重复；修改影响预览；失败保留编辑；成功后失效相关验证而不清空旧记录 |

设备转交遵循现有占用/会话保护，不因新集合允许多台就绕开。设备停用/离线后所有消费页读取当前状态，历史证据媒体不因此自动删除。

### 4.2 设备与通用列表

设备详情显示绑定工位和视角角色，列表可跳回工位；新相机类型若未在现有类型枚举中，不擅自新增多种硬件类别，可沿用全景/细节相机加用途。

创建/编辑/停用的影响说明一致；删除被配置/快照引用的设备采用已有保护和历史保留，不能只从工位数组删除留下悬空引用。

## 5. SOP工位配置与验证

AI配置详情的工位块显示判断项所需区域与视角覆盖矩阵：行是条件/逻辑区，列是当前相机；每格显示已映射、缺映射、离线或不适用。

判断项单视角默认沿用旧相机；改为任一/共同策略时逐条补证据，不自动选全部相机。区域编辑切相机保留各自矩形，未保存切换提示保存/放弃。

配置检查至少包括：相机归属、所需流状态、视角策略、区域合法性、同一人/对象要求是否有实现、时间关系、模型输出能力与真实/演示用途。

现场案例新增：身份交接成功、交接不明、同款衣着、教师短时入镜、区域错序、关键相机缺失、可选相机缺失、车位/相机变化。每案例对应具体判断项和视角；演示通过仍不等于真实跨镜头算法通过。

改某区域相机仅使受影响配置/项待重新验证；若当前整工位启用结构不能精确表达，保留总门槛并明确受影响项实际降级，不能静默放过。

## 6. 跨区域身份与运行行为

原Session仍绑定一个主学生。新增相机局部轨迹与全局操作人关联记录：相机、局部Track、关联状态、有效时间、来源（算法/教师/演示）及依据。当前合成`track-Session`只作为历史演示标识，不当作真实跨镜头匹配证明。

| 情况 | 行为 |
| --- | --- |
| 同一区域身份明确 | 正常记录该学生事实 |
| 转入另一相机，关联证据足够 | 在有效关联区间内消费新视角事实，留交接记录 |
| 暂时丢失/无法确定 | 保存观察但不归为学生完成，相关要求未知 |
| 教师人工确认同一人 | 记录确认人、理由、范围和时间，不追溯伪造算法关联 |
| 多人进入/可能串人 | 提示身份待核，不能按最近位置自动归属 |

未知身份不直接扣分；需要暂停的技术/安全情形仍按现有机制处理。普通恢复不能把身份或证据不明自动改为有依据。

局部故障：可选相机缺失不影响不依赖它的项；任一策略尚有充分可靠视角可继续；共同证据缺一项则该要求未知。主机/核心录像等影响继续的故障仍走原暂停处理，不为“局部降级”弱化安全。

## 7. 准备页、预览、回放与统计

### 7.1 准备与学生端

首次开放锁定相机集合、区域映射、判断策略及模型/配置快照。预览沿用默认主视角，镜头不在线显示原因；不能静默换一个未验证镜头继续宣称自动评价正常。

学生练习端不展示复杂技术拓扑；只给必要业务提示。考试端相机/区域切换不得泄露正确检查点、教师标准与实时结果。旧工位重定向继续有效。

### 7.2 教师总览/单人监控

默认主视角＋可用辅助列表，保留现有卡片和放大交互；切换预览只改变观看镜头，不改变判断项绑定或主相机配置。

选择某Step/事件时优先显示其证据相机，不能始终拿主相机画面代表所有步骤。无可播放证据显示缺失，示意图/示教不冒充现场画面。身份关联未知和区域事实分开展示。

### 7.3 报告与证据

一条要求可关联多个片段，每段含相机/区域、起止、可用性、时间对齐依据。页面提供视角切换与定位；只有真实媒体和对齐信息齐全才提供同步回放。未接入时只展示可解释索引或明确演示，不伪造同步播放。

旧单证据字段适配为一个证据来源，保留timeRange/evidenceSources等原字段读取；录像到期显示不可用但不抹去原判/审计。导出包含区域/视角与缺口，不把画面切换次数作为动作次数。

### 7.4 数据大屏与管理员

`dataScreenRules.js`和学生主相机选择器必须使用共享选择逻辑，不能继续只读fallback来判断“有辅助”。考试保持画面/步骤保护，独立演示不并入业务统计。

管理员技术诊断可见视角覆盖、关联和缺流；教师只见业务可用性。部分相机缺失不一律显示整个单元“全部不可用”，同时也不能用一台在线掩盖必需证据缺失。

## 8. 演示数据与旧记录

保留全部旧工位/设备ID及已绑定关系，旧主/第二视角迁移后仍能预览状态和进入配置。不要直接把既有6个工位全部改成汽车全场景。

追加一个独立多区域演示实训单元及相机/区域记录，按实际页面支持配置若干视角，数量只是演示。样例至少包含：

1. 单相机旧工位无损加载。
2. 旧主/第二视角有显式判断绑定且角色待确认。
3. 新多区域，单视角、任一、共同证据各一项。
4. 同一逻辑区在两相机映射，编辑一条不丢另一条。
5. 可选相机离线而无关项可用；必需相机离线而相关项未知。
6. 工作台→车周→驾驶舱→车底的身份交接演示，含一次未知和教师确认。
7. 走过车周但具体检查无证据，不显示检查完成。
8. 旧历史快照、新多视角证据、过期媒体、未发布考试保护。

新增Session锁定对应配置，模拟身份与片段明确标演示。采样数据按同一次演练sourceGroupId统一，不把不同相机录像随机拆到训练和测试。

## 9. 迁移与执行顺序

1. 增加共享相机集合/证据选择器，旧字段适配，先让旧单/双视角全部通过。
2. 更新物理配置和设备关系所有写入口，补活动占用/释放检查。
3. 更新判断项多视角、复合区域映射、检查与失效；Tab和瀑布同步。
4. 将门槛、快照、准备、学生、教师、管理员、大屏所有读取切到共享选择器。
5. 增加身份关联/多证据记录与模拟场景；与第三批同一事件核心对接。
6. 同步CPD、seed、新工位/新会话工厂，保留旧快照，执行迁移和跨模块测试。

## 10. 必测与完成证据

- 旧主/第二视角不丢，旧单cameraId绑定继续有效；旧字段与新集合无双真源冲突。
- 跨工位设备不能误绑定；有运行依赖不能静默转交/删除。
- 同逻辑区两镜头映射互不覆盖；百分比/像素/归一化一致。
- 切观看镜头不修改AI配置，修改配置会触发正确范围重验。
- 镜头失效按策略和依赖处理，身份未知不自动归人，不从进入区域推导检查合格。
- 旧/新快照并存，运行中不热切换当前新相机；历史证据过期不改原成绩。
- 学生/教师预览、管理员、报告/CSV、大屏对同相机状态一致；考试隐私不泄露。
- 多相机同次演练不能跨数据集，来源切换保持两份数据完整。

建议回归：workstation-ai、sop-workstation-ai、ai-runtime/store、student-practice-rules、student-exam及联动、data-screen、storage-migration、current-prototype-data、架构集成与相关e2e夹具。真实跨镜头精度、多路推理和时钟同步属于现场试验，不以演示测试替代。

完成须附旧/新相机适配清单、所有消费者调用核对、演示链、关联/证据/局部故障测试和构建结果。当前均未实施。
