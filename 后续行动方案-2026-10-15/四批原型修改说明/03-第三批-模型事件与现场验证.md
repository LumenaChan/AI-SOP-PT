# 第三批修改说明：模型、连续事件与现场验证

日期：2026-10-15。状态：原型改造已实施；实际覆盖、验证结果和生产接入边界见[实施台账](05-实施台账与演示入口.md)。依赖[共同约束](00-共同约束、影响清单与数据保护.md)及前两批数据；本批完善前端原型的任务/运行契约与演示闭环，不包含真实模型下载、训练服务或摄像头推理上线。

## 1. 目标与两种验证用途

明确区分“原型演示可运行”和“真实现场可启用”。原型仍可演示训练、发布、动作与安全流程；模拟指标/录像占位不得满足真实门槛。尚未接真实服务时，真实现场路径显示待接入及缺项，不伪造成功。

主链：候选模型/已有模型 → 独立评测记录 → 发布当前能力模型 → 工位验证 → 锁定教学快照 → 观察与动作事件 → 判断项 → 完成/评分/安全候选 → 证据与复核。

## 2. 必查影响矩阵

| 对象 | 主要代码 | 跨模块消费 |
| --- | --- | --- |
| 模型任务/产物 | `aiModelTrainingRules.js`、`aiModelPublishingRules.js` | 能力列表/详情、引用下拉、发布影响、原快照 |
| 配置可用性 | `aiCapabilityRules.js`、`aiCapabilityConfigRules.js`、`aiEntry.js` | 所有状态摘要、工位验证、准备页、管理员首页、大屏 |

主Provider与独立runtime store必须调用同一规则核心。隐藏的旧AI评价调试路径若共用数据，不得成为绕过真实验证、评分与来源规则的后门。

## 3. 模型任务与发布数据

### 3.1 任务来源与字段

| 项目 | 规则 |
| --- | --- |
| 候选来源 | 本平台训练、已有模型适配/验证；沿用能力语义，不为验证外部模型伪造训练任务 |
| 结果来源 | 原型模拟、真实模型执行、人工录入/导入、历史未核实；人工录入不是模型执行 |
| 输入/输出 | RGB或可选RGB＋关键点、裁剪/采样配置、能力输出结构；不是要求用户自己写任意代码 |
| 内部追溯 | 任务、模型产物、数据快照、参数、执行环境、评测报告、时间与操作者 |
| 适用条件 | 工具/工件/可见性、已验证限制，不随模型名称自动推断 |
| 许可/交付记录 | 模型来源与运行方式，生产采用前核对；原型演示不自动取得真实授权 |

现有short_action等预设仍可保留为演示参数，但页面不得把它们描述成已经部署的具体算法。真实服务未接入时不能启动一个看似真实完成的计时器任务。

### 3.2 发布检查

| 条件 | 原型演示 | 真实现场 |
| --- | --- | --- |
| 产物与输出兼容 | 可用明确演示产物 | 实际产物/服务可验证，结构匹配 |
| 验证/测试报告 | 演示结果带标识 | 与候选和独立数据匹配；实际报告可追溯 |
| 数据分组/负例/未知覆盖 | 演示检查可运行 | 必须满足锁定评测方案与分组要求 |
| 性能与环境 | 显示尚未实测/演示值 | 与目标运行条件对应，不能只填百分比 |
| 发布结果 | 可供原型配置演示 | 能力库发布后仍要对应工位现场验证 |

原先只依赖训练任务字段的发布路径扩展为统一候选对象，保留旧trainingTaskId兼容；现有记录不强造新ID或真实报告。用户仍只维护当前模型，不新增版本兼容审批。

重新发布使受影响工位待重新验证，新会话不得复用失效条件；已有会话保持其已锁定快照。需要回退时管理员/实施通过内部发布记录恢复当前模型，记录原因和验证状态。

## 4. 训练/发布/能力页面

训练页保持参数、任务、日志布局；增加候选来源、结果来源与评测摘要。动作分类准确率与事件级完整视频指标分开展示；无事件评测显示未记录，不用分类准确率代填。

已有模型适配分支不展示epochs等不适用参数，改为模型来源、输入输出、验证材料；返回训练分支恢复草稿，不把无效隐藏值写入候选。

取消/失败/重试留日志；提交防重复；源数据准备状态改变时影响新任务，不修改已经锁定的数据。导入报告校验候选标识与数据范围，错误保留输入并明确原因。

发布页预览受影响配置和工位；不能因模拟门槛通过变为真实可用。能力详情、选择下拉和配置摘要同步显示“可演示/待真实验证”等状态，不出现页面说已发布、选择器却无解释地消失。

## 5. 连续观察、事件聚合与状态

### 5.1 三层对象

| 层 | 最低内容 | 作用 |
| --- | --- | --- |
| 原始观察 | Session、能力/来源、时间、相机/操作人关联、对象/动作候选、可见性、证据 | 保存看到了什么，不先宣告步骤完成 |
| 动作事件/持续状态 | 独立事件标识、起止、完整/中断/重复、关联对象；或当前有效/失效/未知 | 合并窗口、计数与持续检查 |
| 判断项结果 | 教师要求/条件、适用时间、事实引用、确认/观察中/未知、完成/评分/安全用途 | 确定性规则消费，不直接让模型评分 |

跨SOP用SOP ID＋Step ID；跨会话、错模型、错配置结果不能用于当前评价。相机/人物关联不明先记未知，不按最近的人补成当前学生。

### 5.2 事件与时间规则

- 记录相关全程事实，当前Step只决定是否可用于某个要求，不在入口把提前/错序事实全部丢弃。
- 一次动作的多个重叠窗口聚合为一个事件；重试同一观察不生成新发生次数；中断后再开始按已定义规则处理。
- 观察持续时间来自事实起止和连续性，不把配置minDurationSeconds当作已经观察到的时长。
- 缺帧/断流/关联失效打断连续性，恢复后是否重计由已验证规则决定；缺失区间不补算。
- 真实采集时间、事件时间、判定时间与通知时间分开。过期/乱序观察可存为审计，不倒改已锁定正式成绩。
- 新Session动作次数以聚合事件计数，模型窗口数量只给管理员诊断，不影响教学计数。

### 5.3 持续状态规则

在教师指定作业区间内，手套佩戴等状态可能从有效→失效或未知。工具移开不必然撤销已经完成的一次历史动作，只有持续要求才继续检查。

不确定只产生未知/注意事项，不自动形成违规；有可见、可靠的负向事实才按已有规则生成相应评分或安全候选。安全候选不直接等于确认违规。

### 5.4 模拟入口

现有“模拟AI识别观察”继续保留为管理员原型工具，改为经统一观察/事件入口消费。支持动作开始/结束/中断、重复同观察、状态成立/失效/遮挡、技术断流、提前动作和纠正。

模拟操作产生的时长明确为模拟输入，标识来源；不能据此显示真实检测耗时。隐藏旧模拟分支如保留，必须调用同一评分/来源策略，不复制另一套实现。

## 6. 现场验证页面

保留AI配置详情内工位配置工作区，继续分“配置检查、现场案例、启用”。新增用途为原型演示检查/真实现场验证；技术明细仅管理员/实施可见。

原八类场景保持，补合法变体、伪完成、真实中断/重复/纠正、持续状态变化及背景观察。案例应归属具体判断项，不能一条通过代表全部。

每案例记录：要求、预期、实际结果、来源、录像/事件、执行人、模型/配置内部指纹、结论。真实现场记录缺来源或真实证据时可保存草稿，不能通过真实门槛。演示案例不能生成真实算法通过统计。

区分“场景已检查”与“独立批量评测通过”：适用自动项均满足约定要求才真实启用；未满足项可改辅助/教师，不阻止课程SOP本身发布和使用。

模型、ROI、机位或关键配置改变，明确列出受影响项进入待重新验证；不能清空所有无关记录或抹去失败案例。旧记录保留展示，真实有效性按明确来源检查。

## 7. 准备、运行、学生与教师联动

准备页清楚显示本次运行用途、计划自动项与降级原因。没有真实服务时仍可演示业务，但不得暗示现场已接入。首次开放锁定SOP/能力/工位/用途快照，刷新不临时改读当前模型。

教师监控显示业务事实和待确认原因；管理员诊断展示窗口、事件、时长、版本不匹配等原因。事件时间轴可关联录像片段；原型占位无真实媒体时显示不可播放。

规则确认才推进完成，政策保分、未知或学生求助不自动推进。结束/交卷保存缺证说明；考试计时、暂停原因和安全阻断维持现有独立约束。

普通整场/单人恢复不能绕过pending安全候选或未恢复且影响继续的技术异常；修复异常后按原入口恢复，不重置既有有效考试时间。状态提醒去重，防每帧产生待办。

报告/CSV区分真实/演示/历史来源，实际AI指标只用可追溯对应范围；预览图、示教视频和真实学生证据不能混用。

## 8. 历史兼容与演示包

旧训练/发布/验证记录无来源时设为历史未核实，不擅自标真实或删除。现有原型已发布与已启用状态继续支持演示，增加用途解释；真实路径必须补证据，不把旧演示状态清空造成全界面不可用。

旧runtime只有aiObservations时，保留原事件，不把每条自动迁成一个独立真实动作；旧观察时长可能来自配置，显示未实测。旧会话score/currentStep/resultStatus保留，不运行新引擎回放重算。

新演示包覆盖：自训练模拟候选、已有模型适配待验证、报告不匹配失败、仅演示验证通过、真实材料缺失不能启用、多窗口合并一次、重复观察不增次、操作中断、纠正、跨步骤事实、手套失效/未知、断流与安全恢复保护。

新模拟事件、判断项、证据与快照完整引用；即使没有真实视频也要明确占位，不伪造磁盘文件。CPD、seed与运行时新会话工厂字段一致。

## 9. 实施顺序

1. 补任务/来源/用途兼容，先让旧页面与演示不失效。
2. 实现统一事件与规则消费核心，两个store通过同一核心；补幂等、窗口和持续状态。
3. 扩展候选、发布检查、配置可用性与工位验证，联动aiEntry/所有摘要。
4. 改模拟工具、准备/运行/学生/报告/大屏所有消费入口。
5. 补新演示包和旧记录只读对照，确保历史分数不变。
6. 执行必要规则、集成、迁移和构建检查，记录限制。

## 10. 必测与完成证据

- 来源/用途区分不会让原型样例全消失，也不会把模拟通过变为真实启用。
- 已有模型无需伪造训练任务；输出/报告不匹配不能发布真实候选。
- 同一动作多窗口只计一次，重复/乱序/旧Session/错配置结果不重复扣分或改判。
- 未知和断流不扣分，连续时长不跨缺失区间；真实未完成与遮挡不同。
- 手套初始戴好后仍可失效/未知；一次检测动作完成不因工具之后移走被随意撤销。
- 安全/技术暂停不能被普通恢复绕过，考试倒计时冻结/恢复正确。
- 配置/模型更新后新会话重新验证，既有快照和成绩不变。
- 教师/管理员/学生、报告/导出/摘要均符合第一批口径。
