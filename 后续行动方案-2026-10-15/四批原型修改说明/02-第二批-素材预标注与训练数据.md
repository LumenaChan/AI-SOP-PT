# 第二批修改说明：素材、预标注与训练数据

日期：2026-10-15。状态：原型改造已实施；实际覆盖、验证结果和生产接入边界见[实施台账](05-实施台账与演示入口.md)。依赖[共同约束](00-共同约束、影响清单与数据保护.md)和第一批术语。目标是在现有能力库内补齐有效数据与预标注，不重建标注平台。

## 1. 端到端范围

原始素材/用途 → 抽帧/切片 → 自动质量建议 → 人工保留 → AI预标注建议 → 人工修改并保存 → 当前训练数据候选 → 分组与训练快照。

正式标注继续只有待标注/已标注，不增加已标注后的审核。AI建议是独立辅助数据，生成不等于人工完成。预标注模型服务在原型中只演示接口与状态，不宣称已接入Seek/SAM等真实算法。

## 2. 现状与完整影响矩阵

| 环节 | 当前代码/页面 | 必查消费点 |
| --- | --- | --- |
| 素材 | `aiVideoRules.js`、AiVideoManagement/Upload/Preview | 编辑/批量/去重/删除保护、原时长/文件引用、能力详情计数 |
| 派生 | `aiExtractionRules.js`、AiExtractionPage | `aiFrames`/`aiClips`、任务统计、时间格式、失败/重复任务 |
| 清洗 | `aiCleaningRules.js`、`aiManualCleaningRules.js`及两页面 | 标注准入、剔除原因、恢复、已标注保护、用途统计 |
| 标注 | `aiAnnotationRules.js`、AiAnnotationPage与框/视频编辑器 | 保存、保存下一条、批量、类别变更、筛选/进度、训练候选 |
| 分组 | `aiTrainingDataRules.js`、AiTrainingDataPage | 分组卡、自动/手动划分、分布、就绪、旧sourceAssignments |
| 训练/发布 | `aiModelTrainingRules.js`、`aiModelPublishingRules.js` | 新标注与来源快照、不改历史结果、主要类别/背景覆盖 |
| 持久化与演示 | Provider、normalize、CPD、seed、storage事件 | 建议任务/新属性不因刷新丢失；两个来源独立 |

源视频属性正常/错误/背景仅作为素材元数据；不能自动给所有派生片段贴相同标签。能力库页面不新增SOP、Step或评分关联列。

## 3. 数据字段与缺省

### 3.1 源素材

| 新属性 | 产品规则 |
| --- | --- |
| 采集批次、演练数据组 | 正式试点要求明确；同一次演练的全部文件同组。已有`sourceGroupId`作为统一组标识，不再并列多个含义相同字段 |
| 匿名参与者、教师/学生来源 | 采样信息，不要求关联真实学号；缺失为未记录，不从文件名猜 |
| 采集日期、工件/工具条件、相机条件 | 支持覆盖分析；有旧capturedAt/workstationId则复用，不另造重复字段 |
| 样本特征 | 标准、合法变化、已知错误、真实未完成、相似无效、背景、不可判定，可多选 |
| 使用范围 | 开发、验证、封存测试；与训练集/验证集/测试集划分区分 |
| 来源变更标记 | 内部追溯实际文件/内容变化；改显示名称不自动失效内容建议 |

### 3.2 图片/片段与建议

派生数据继承源组、参与者、条件与用途，保留sourceVideoId及精确时间。正式人工结果沿用boxes、noTargetConfirmed、actionCategoryId、refinedStartMs/endMs及annotatedBy/At。

新增建议独立保存：建议任务ID、样本/能力、源内容与当前人工标注基线、类别词表标记、原始结果、解析结果、失败原因、建议状态与人工采用时间。建议不能占用正式boxes/actionCategory字段。

轻量辅助属性：动作完整性（完整/真实未完成/源片截断）、可见性、能力定义的合法变化/错误类型、后续用途。关键帧对象关系仅在能力确实需要时提供；不要求全量骨架或时空多人框。

## 4. 页面行为

### 4.1 视频管理

复用`/admin/ai-capability-library/videos`上传与编辑。新增采样信息折叠区和按组/参与者/用途筛选；默认仍以当前能力隔离。批量改用途预览数量与受影响训练数据，已锁定任务不改。

同组新视频加入时继承用途；组用途冲突提示统一处理，不能静默换集合。已有源素材产生派生数据后的删除保护保留。替换实际文件使用新来源记录或明确修复操作，不能借改文件名覆盖证据。

只有真实文件/可访问位置成功保存后才能标真实上传完成；浏览器临时blob引用刷新可能失效，页面必须说明并保留元数据，不能把文件不可读当无目标。

### 4.2 抽帧/切片

沿用手动/定长、间隔/帧率模式；增加“动作候选切片”任务入口与演示来源。字段包括处理范围、候选动作（能力词表）、上下文保留策略；输出仅为待处理派生数据，仍走清洗。

统一源视频时长解析：当前源视频有格式化duration，部分保存逻辑读取durationMs。实施必须使用同一合法时长函数校验切片和微调，不能因durationMs缺失就放过越界。

保留动作前后背景；候选重叠标记供检查，不默认为不同事件。真动作中断与视频被截断分别标记。任务处理中可离开/返回/取消，取消仅停止剩余项，已产生结果可追溯；失败项重试不重复派生已成功项。

### 4.3 自动清洗

只输出可解释质量问题和建议用途。针对业务负例与不可判定样本，清洗建议不能等同于真实行为标签。

| 情况 | 建议处理 | 是否可直接丢弃业务负例 |
| --- | --- | --- |
| 文件损坏/全黑 | 修复或建议剔除，保留源引用和原因 | 不以其作为操作错误标签 |
| 模糊/遮挡 | 建议人工查看；可保留未知验证用途 | 否 |
| 过短片段 | 结合当前任务提示边界/时长问题 | 否，不能统一最短时长剔除所有几秒动作 |
| 内容高度相似 | 显示重复依据；罕见负例允许保留 | 否 |
| 操作未完成/做错 | 不是画质剔除条件 | 否 |

保留原宽松/标准/严格模式，新增用途提示不改变已有人工保留结果。旧模拟质量指标注明演示，不当作真实清洗测量。

### 4.4 人工清洗

保留当前已保留/已剔除。将原“动作不完整”拆清：真实操作未完成应保留并选负例用途；裁剪不完整则重新切片/修边界；若内容无用才剔除并给原因。

批量保留可指定共同用途，预览覆盖情况；选择不同用途时不抹掉每条原属性。已进入正式标注的记录不能静默改清洗，沿用现有保护，提供定位标注/清理说明。已被训练使用的历史快照不改。

### 4.5 数据标注工作台

继续原图/片段、类别、框编辑、时间微调、保存/下一条布局。新增建议任务栏、建议显隐和采用/不采用操作。当前正式标注筛选与建议筛选独立，不把待确认建议混作已标注。

| 操作 | 前置/校验 | 成功后 | 失败/并发 |
| --- | --- | --- | --- |
| 生成建议 | 人工已保留、来源可用、类别存在、非封存测试 | 创建独立任务，正式结果不变 | 显示失败原因；原人工路径仍可用 |
| 采用建议 | 建议结构合法且源/词表/人工基线仍匹配 | 填入编辑草稿，不自动保存 | 过期建议不能覆盖新人工结果 |
| 修改保存 | 原有框/类别/时间校验＋用途一致性 | 标注completed，记录操作者与时间；候选统计同步 | 校验失败保留草稿；重复点击不重复写 |
| 不采用 | 有当前建议 | 保留拒绝记录，正式结果不变 | 不删除源样本 |
| 无目标 | 人工明确勾选，现有二次确认 | 清空框并保存无目标 | 模型未返回不能自动触发 |
| 重新生成 | 已有结果时明确不覆盖正式标注 | 新任务/建议单独存 | 后台完成不能覆盖正在编辑草稿 |
| 批量采用并保存 | 首试默认关闭；试验后开放时主动勾选、预览、逐条合法检查 | 仅合格且未被人工改动项保存，报告跳过数 | 无目标建议不批量自动接受；部分失败保留成功项 |

动作片段仍一个最终动作类别；背景不可删除；错误类别按能力需要配置。完整性/可见性为辅助属性，不自动生成每个SOP步骤的正确/错误复合类别。

封存测试金标准不批量送被比较模型预标注，避免测自身标签。独立专家判定在试验清单处理，不增加标注审批产品。

退出/切能力/切数据源时处理未保存草稿；返回后保留队列位置。后台任务刷新后恢复任务状态，但演示处理中任务不能凭页面重载跳成真实完成。

### 4.6 训练数据

同组源文件和派生数据整体划分。现有sourceAssignments保持兼容读；同sourceGroupId的旧分配若冲突，提示“同次演练跨集合，需统一”，保留旧记录，不自动重排历史。

展示候选合法性、组、匿名参与者、用途和负例覆盖。封存测试不被自动分入训练/调参验证；未记录参与者的旧数据可继续演示训练，但不能证明真实跨人独立测试。新增同组数据继承集合或使该组待确认，不能悄悄进入另一集合。

按组操作成功后同步分布、类别覆盖和就绪；背景、错误、未知验证分开。不可判定验证样本不强塞成背景训练标签。每次训练冻结当时的素材、标注与划分；修改当前标注只影响后续任务。

### 4.7 其他消费页面

能力详情的原始视频、派生、人工已标注、训练有效数应从真实当前集合推导，不继续硬编码0；各数字各自分母，不用建议数代替标注数。

训练页读取新候选/组检查并保留旧任务。发布页只读取对应任务快照与结果，不因当前素材修正改变旧报告。日志记录生成/采用/保存/划分的区别，不每次展示新增审计。

## 5. 任务状态与异常矩阵

| 状态 | UI/操作 | 数据后果 |
| --- | --- | --- |
| 待处理/处理中 | 可查看任务，防重复，可取消剩余工作 | 正式标注不变 |
| 完成、待确认建议 | 对照/采用/修改/不采用 | 未保存不入训练 |
| 部分失败 | 显示成功/失败数，只重试失败项 | 成功建议保留 |
| 全失败/取消 | 显示原因，人工操作可继续 | 不制造无目标 |
| 来源/词表已变 | 建议标过期，允许重新生成 | 不覆盖当前人工标签 |
| 无权限/对象删除 | 阻止提交，返回列表/重新选择 | 原训练快照保留 |
| 存储失败 | 未保存提示，保留草稿、导出途径 | 不显示成功 |

## 6. 演示数据包

保留现有14源视频、91帧、44片段的ID和标注。追加与能力关联的样例，不用替换整份CPD强制显示新功能。

至少覆盖：清晰目标框建议、漏框待补、AI无目标但实际有目标、真实无目标人工确认、动作边界微调、真实未完成被保留、源片截断退回、遮挡未知用途、部分任务失败、已人工改动导致建议过期。

训练划分样例包含：同组两文件在同集合、旧同组跨集合待修复、封存测试保护、缺参与者但保留旧数据。新增建议始终不直接写annotationStatus=completed。

已有分类/发布任务快照原样保留，新增演示任务明确使用新增数据。刷新、换来源后至少一条未处理、一条待确认、一条已人工保存、一条失败均能展示。

## 7. 迁移与执行顺序

1. 新属性缺省为未记录，建议集合缺省空；旧completed仍为已标注，不一律退回。
2. 统一时长与来源合法性，再改清洗与标注准入。
3. 建议任务与正式结果分存，更新保存/批量/类别保护与Provider方法。
4. 改全能力库页面与计数，再升级分组/就绪和训练快照。
5. 同步CPD、seed、新建工厂及演示清单；锁定旧任务读取不变。
6. 依共同文件检查来源切换、写入失败和跨标签刷新。

## 8. 必测与完成标准

- 旧标注/类别/框/边界加载不丢；时间不能因字段缺失越过原视频。
- 未完成业务负例可进入标注，文件损坏不会被当作错误动作金标准。
- AI建议不能直接入训练；采用后未保存也不能；正式人工保存后各页数量同步。
- 后台任务/重试/批量不会覆盖人工结果，未知不会自动变无目标。
- 同组不跨集合；测试用途不能被自动分配到训练；当前标注修改不影响历史任务。
- 两种来源均有样例，切换不污染另一份数据；存储满不提示成功。

现有相关测试：ai-video、ai-extraction、ai-cleaning、ai-manual-cleaning、ai-annotation、ai-training-data、ai-model-training/publishing、current-prototype-data、storage-migration与架构集成。后续补规则和跨模块契约，不为按钮文案重复大量测试。

完成记录需附建议/正式结果计数对照、组隔离结果、旧快照未变对照、演示路径和测试/构建结果。当前均未实施。
