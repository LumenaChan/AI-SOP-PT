# 产品原型改造方案

日期：2026-10-15。用途：指导后续分批原型实施、业务评审和测试。所有新增设计为建议，当前没有写入应用或修改历史成绩。

本方案依据当前实际路由与组件，复用已有菜单。以固定工作台为第一阶段，以多区域为第二阶段；不恢复已隐藏的旧 AI 评价或教师 Mapping 调试入口。

既有边界依据：[一期重构总纲](../xingchen-prototype/docs/0924modify/00-AI-SOP一期重构总纲.md)、[SOP去版本化](../xingchen-prototype/docs/0924modify/01-教师端SOP去版本化.md)、[现有数据标注规则](../xingchen-prototype/docs/0924modify/08-AI能力库-数据标注.md)。本次对预标注的增量扩展以“建议先确认再保存”为边界，不恢复过去取消的标注审批体系。

## 1. 全局规则与权限

对齐现有一期重构总纲：继续采用“SOP标准＋AI能力配置＋AI能力库”。SOP发布后修改使用“复制创建”产生新独立SOP；一个SOP一套当前配置；不恢复SOP/映射/数据集/模型的用户可见版本管理。技术追溯使用内部任务ID、文件标识、保存时间和锁定快照，不要求用户维护版本号。

预标注的人工作业采用“检查建议并保存”的轻量方式，不新增独立标注审核菜单、审核员角色或两级审批。正式标注继续为待标注/已标注。AI建议待确认是新增建议状态，不是已标注后的另一道审批。

### 1.1 分开的四种状态

| 状态维度 | 表达内容 | 不可混用 |
| --- | --- | --- |
| 识别/证据状态 | 可见事实、未观察到、不可见、不确定、系统异常 | 未观察到不直接等于未执行 |
| 任务完成状态 | 未开始、观察中、证据支持完成、学生提交、教师确认、无法自动确认 | 默认保分不等于完成 |
| 评分处置 | 按规则保分、已有评分规则结果、教师审计改判 | 完成不一定意味着所有工艺要求合格 |
| 运行可用性 | 模型/配置是否就绪、真实或模拟来源、工位验证是否有效 | 模型发布不等于工位已能自动评价 |

执行前每类状态形成唯一字典，各页面从共享状态计算；不能在某页自行把“已标注”或“满分”改写成“AI正确”。保留原会话流程状态，新增独立判定/证据字段，不用一个新枚举覆盖所有原状态。

### 1.2 角色边界

- 教师：定义标准、查看业务覆盖/证据/未知、确认安全候选、按现有权限复核成绩。默认不编辑模型参数、部署与管理员 ROI。
- 管理员/实施：配置能力、数据流程、模型候选、区域/相机、现场验证与技术诊断；既有管理员成绩页面继续只读。
- 算法/标注工作暂由管理员侧承载，不新增一个未定义权限的账户体系；以后需独立标注角色时另做权限设计。
- 学生：沿用会话绑定操作端，练习显示允许的教学反馈，考试隐藏标准与实时评价。

### 1.3 真实和演示数据

新增任务与结果记录带来源：原型模拟、真实模型、人工记录、导入报告。页面明确来源，统计分开计算。模拟结果可验证原型交互，但不能满足真实模型/工位上线条件。

“导入真实报告”必须保存报告文件/位置、测试数据版本、模型版本、执行环境与记录人；只手工填一个百分比不能变为可验证的算法成绩。

## 3. SOP 编辑与详情：先把“检测什么”写清楚

### 3.1 新增“可评价要求”区域

沿用教师标准内容、操作要点、常见错误、视觉限制、示教媒体和三种评价模式。在每步内增加可见要求列表，不把算法名称放进教师教学内容。

| 字段 | 规则 | 联动 |
| --- | --- | --- |
| 要求名称 | 必填，短句；同一步内不重名 | 显示在配置、监控与报告 |
| 判断目标 | 选择动作发生、结果状态、操作过程要求；同一步可建多个要求 | 状态类显示是否持续；过程类显示子要求和顺序 |
| 要求说明 | 必填，由教师描述合格条件 | 管理员配置时只读引用 |
| 对象/部位描述 | 涉及指定工具/工件/测点时必填 | 关联配置需要的检测对象与区域 |
| 允许变化 | 默认空并提示需审视；例如左右手、速度变化 | 为采集和标注提供合法变体，不自动改变评分 |
| 不合格示例 | 有明确错误时填写，可多条 | 关联负例和现场测试案例 |
| 不可判定条件 | 自动/辅助要求必须填写；例如表笔接触点不可见 | 触发未知与保分说明 |
| 证据要求 | 自动/辅助时必填，说明必须看见什么 | 映射到判断项和证据片段 |
| 持续检查范围 | 仅状态类可选：当前步骤或教师指定作业区间 | 生成跨步骤持续条件；不默认一直监测全部课程 |
| 穿戴过程是否考核 | 仅穿戴类需求适用；默认由教师明确选择 | 已戴好可接受时无需强制镜头内穿戴 |

时长或阈值已属于教师标准时保留业务单位；纯模型参数仍由管理员设置。字段在隐藏时保留草稿，但不参与有效规则；切换目标显示影响提示。

### 3.2 保存、复制创建与异常

- 草稿保存检查必填与引用合法性，失败保留输入；缺少配置不阻止草稿或正式 SOP 的正常业务发布。
- 已发布 SOP 的要求变更沿用“复制创建”，形成新的独立 SOP ID，再独立配置AI；原 SOP 及其已有会话不变。当前AI配置修改则按受影响范围进入待重新验证，不创建配置版本。
- 详情显示自动评价适用条件与覆盖；无 AI 配置时显示“尚未配置”，不展示不存在的模型结果。
- 旧 SOP 没有新结构时保留原完成条件和现有评分，不自动拆成机器要求。标为“待补充可评价要求”，仅影响新增自动化配置，不追溯改变旧会话。

验收：允许学生提前戴好手套的标准不会被配置为必须识别穿戴过程；复制修改视觉要求不会修改旧 Session；视觉无法确认的数值仍为教师要求。

## 4. AI 能力与 SOP 配置：分清模型输出与业务完成

### 4.1 能力管理

保留“目标检测”和“动作识别”两类。先在现有能力上补“输出含义”：目标框、动作事件；状态/关系结果通过判断项或明确的组合输出表示，避免一开始新增大量能力类型。

字段包括输出对象/动作定义、适用输入区域、输出结构版本、已验证条件、已知限制。识别含义发布后锁定；改变含义创建新能力，不复用旧 ID 改名。

### 4.2 判断项配置

在现有步骤行、教师标准与判断项区域内补充下表；保留 Tab/瀑布展示和管理员紧凑字体。

| 新字段/控件 | 校验与交互 |
| --- | --- |
| 对应教师可见要求 | 从当前 SOP 已发布标准选择，不能由模型新增 |
| 观察目标 | 从教师要求带入，只读；管理员选择实现能力 |
| 事实组合 | 沿用全部/任一/顺序；增加同一操作人/对象关联要求的明确配置 |
| 时间范围 | 当前步骤窗口、前置动作窗口、指定作业区间；记录事实与是否可用于此要求分开 |
| 完成证据 | 动作事件、最终状态或二者；缺配置不能开放相应自动项 |
| 持续状态 | 当前有效/失效/未知条件、检查区间与恢复条件 |
| 不确定处理 | 固定保分与教师注意事项，不开放“遮挡直接扣分”选项 |
| 过程不完整处理 | 已知未完成与画面不足分开；只有可靠证据及匹配规则才能产生违例候选 |
| 同一操作次数 | 以聚合后的动作事件计数，不以模型窗口次数计数 |
| 配置影响预览 | 展示受影响判断项、工位、当前模型与正在运行会话；修改当前配置后重新验证，新会话用当前配置，已锁定会话不变 |

状态类开始成立后仍可能失效或未知；不将一次出现永久锁为“完成且安全”。过程类完成后若规则不要求持续，则不因后来工具移走随意撤销历史完成。

禁止把 AI 无输出直接解释为没做。负向事实需要可见性、观察窗口、身份、数据完整性与规则共同支持；安全候选仍由既有机制确认处置。

验收：手套框数量不能单独代替佩戴关系；多次窗口命中只记一次动作；提前事实有记录但是否有效遵循时间范围；未识别不直接扣分。

## 5. 视频管理：采集元数据与样本用途

保留正常/错误/背景的数据属性，但不把上传属性当作最终标注结论。

新增字段：采集批次、演练Session/数据组、匿名参与者编号、教师/学生来源、拍摄日期、场景/工件/工具版本、采集配置版本、预期样本类型、用途（开发/验证/封存测试）、完整录像关联。

预期样本类型支持标准、合法变化、已知错误、真实未完成、相似无效动作、背景、不可判定；最终结论由标注审核产生。一个原始视频可以包含多种片段，上传属性不强制覆盖全部派生标签。

- 创建时参与者、数据组、采集配置为正式试点必填；历史素材允许缺失但显示“分组信息待补”，不能据此证明独立测试。
- 同次演练不同相机统一数据组；之后补的同组素材继承用途，不能进入另一集合。
- 封存测试用途由管理员控制，默认不向训练流程提供标签，不进入主动挖掘和模型调参。
- 上传/导入失败保留元数据与任务失败原因；文件未真实保存时不能标为上传完成。

验收：能按参与者、批次、样本类型筛选；演练与源文件均可追溯；只修改显示名称不改变分组；替换实际文件需新来源或修订记录。

## 6. 抽帧/切片：完整事件与困难样本

沿用间隔/帧率抽帧、手动/定长切片。增加“动作候选切片”异步任务：来源模型、相关动作词表、时间范围、输出候选段、状态与失败原因。第一版可以模拟任务，但来源明确。

- 候选段只是建议，后续审核调整边界；输出重叠段在界面标出，不自动当作不同动作。
- 保留动作前后过渡和空闲背景；具体前后保留时长依据任务试验，不能统一裁成只有成功瞬间。
- 展示动作开始/结束是否完整、是否为真实中断、素材是否截断；“真实未完成”与“源视频截断”独立。
- 片段太短只给提示或按任务用途处理，不对所有短动作一律剔除。
- 自动任务允许离开后查看、取消、对失败项重试；重试不覆盖已人工保存的标注，成功与失败数量分别保存。

验收：只有半个操作但录像完整的真实错误能保留；因错误切片缺失起点可退回重新切片；定长片段可调边界并追溯原视频。

## 7. 自动/人工清洗：避免删掉要学习的错误

### 7.1 清洗原因拆分

| 素材情况 | 处理 |
| --- | --- |
| 文件损坏、全黑、内容无关、无独立价值的重复 | 建议剔除或修复；人工可复核 |
| 动作本身只做一半、漏动作、错误后纠正 | 标记业务负例，保留；不能用“动作不完整”自动剔除 |
| 片段裁剪缺少应有起点/终点 | 返回重新切片；源视频保留 |
| 遮挡或关键部位不可见 | 可保留到不可判定/鲁棒性验证用途；不能自动标成无目标 |
| 低质量但事件罕见/负例重要 | 显示质量问题与用途，人工决定；不能只凭统一阈值丢弃 |

第一版自动清洗重点是可解释质量问题，业务“做得对不对”交给标注。保持人工清洗已保留才能进入标注的现有规则。

### 7.2 人工操作

保留/剔除时新增“后续用途”选择：目标/动作训练、已知负例、不可判定验证、背景、重新切片。可批量处理，但不同原因或用途不得无提示地统一覆盖。

剔除必须理由；恢复自动建议剔除的数据需说明。已进入标注的数据继续不能被静默重新清洗；先按现有规则清理当前标注。已被训练使用的历史数据/标注快照保持不变，当前素材修改只影响后续候选。

验收：真实未完成不会因其失败而剔除；遮挡验证样本能保存且不被伪造为正常目标标签；质量计数和标注可用数分别统计。

## 8. 数据标注：预标注建议与人工保存

### 8.1 页面结构

复用当前能力选择、待标注/已标注队列、图像框或视频片段编辑区、类别管理与进度。增加：

- 顶部任务区：生成预标注、任务状态/来源、待确认建议数量与试验耗时入口。
- 建议筛选：尚无建议、待确认、已采用、未采用、生成失败；漏检风险和边界不明标签。
- 建议对照：AI结果可显示/隐藏，与当前人工标注分层，人工修改高亮。
- 操作：采用建议、修改、保存、保存并下一条、不采用；无目标仍需主动确认。

不新增全局审核菜单、不分配审核员角色。任务详情可用页内区域/Drawer，保留能力、图片/片段、筛选上下文。人工计时用于本次试点对照，不扩成标注员绩效系统。

### 8.2 标签与业务解耦

| 数据 | 标注方法 |
| --- | --- |
| 动作是什么 | 原有一个最终动作类别与必需的背景/非目标动作；不强制把所有错误都改成背景 |
| 何时发生 | 原有起止时间微调，内部保留变更时间 |
| 完整性/可见性 | 轻量辅助属性，区分完整、真实未完成、素材截断及关键证据不可见 |
| 对象与关系 | 能力确有需要时补关键帧框及可复用关系，例如手套佩戴/手持；首批只对两个试点所需数据开放 |
| 合法变体/已知错误 | 使用当前能力定义的样本属性或必要类别，不带具体SOP评分和Step标签 |

AI能力库继续不展示SOP、Step、评分规则与安全规则。教师要求的对应关系放AI能力配置和现场评测清单，不加回标注页。一个片段仍只有一个最终动作类别；辅助属性不自动变成复合训练类别。不可判定不能强行标成无目标或背景。关键点为可选算法附加信息，不要求全量人工骨架标注。

### 8.3 任务与保存生命周期

预标注任务：待处理 → 处理中 → 完成/部分失败/失败/已取消。每次任务保留任务ID和日志，不覆盖此前人工结果。

建议状态：无建议 → 待确认 → 已采用/部分采用/未采用。生成失败另显示失败原因。**建议生成不会改变正式标注状态；只有人工检查并保存后，才从待标注变成已标注，直接进入现有训练候选规则。**

- 仅人工清洗已保留、非封存测试、来源未改变的数据可批量生成建议。
- 建议坐标/类别/时间非法或无返回，记失败；不能自动补成“无目标”。
- AI类别必须映射已有词表，不能自动创建类别或SOP步骤。
- 采用建议只填充编辑草稿；保存时仍检查框、类别、时间和无目标明确确认。
- 已有人工标注的样本默认不覆盖；主动重新生成时新建议单独存，当前标注保留，直到用户修改并保存。
- 批量保存必须主动选数据、预览影响数量并确认；首试阶段不开放自动建议“无目标”的批量接受。批量能力待质量试验通过后再开放。
- 上游源文件、类别或当前标注发生变化时，旧建议标记不适用；不能覆盖后来的人工作业。
- 用户切换图片/能力或离开时，有未保存修改则提示保存或放弃；后台处理中可以离开，返回恢复任务。
- 重复点击保存不重复生成记录；对象失效/被剔除时阻止保存并保留草稿供核对。
- 已被训练使用的数据允许修改当前标注供下一次训练，已经启动/完成任务的历史快照不变；不新增用户可见标注版本。

### 8.4 状态与操作矩阵

| 当前情况 | 生成建议 | 人工修改/保存 | 进入训练候选 |
| --- | --- | --- | --- |
| 待标注、无建议 | 可 | 原人工路径可用 | 保存合法结果前不可 |
| 待标注、处理中 | 不重复发起；可取消 | 可，后台不得覆盖草稿 | 人工合法保存后可 |
| 待标注、待确认建议 | 可重试并留日志 | 采用/修改后保存或不采用 | 建议本身不可，保存后可 |
| 已标注 | 主动操作且默认不覆盖 | 继续允许修改当前标注 | 满足现有条件可 |
| 生成失败/已取消 | 可重试 | 原人工路径可用 | 按正式标注状态判断 |
| 已被训练使用 | 新建议不改历史快照 | 当前修改只影响后续候选 | 旧任务用旧快照，新任务用当前标注 |

耗时记录采用试点计时表或轻量可暂停记录，区分任务管理、修改、检查与抽检；没有记录显示“未记录”，不拿模型推理时间冒充人工节省。

验收：生成建议后训练候选数不增加，人工保存后才增加；未知不当作无目标；不新增独立审核流程；重试/取消/刷新不丢人工结果；当前修改不覆盖历史训练快照。

## 9. 训练数据：划分、封存与内部快照

当前按源视频分组是保留基础。第一阶段提升为演练Session/数据组优先，并增加参与者、日期与采集条件的跨集合检查。

- 同组全部源文件和派生数据必须同一集合；管理员移动时预览整组，不只移动选中帧。
- 已封存测试的参与者/Session默认不进入训练或验证；如开放其错误供调参，标为开发数据并建立新的封存测试。
- “不可判定验证”用途不被默认当成动作分类的错误标签；训练使用哪些属性由模型任务明确选择。
- 每次训练锁定素材、当前人工标注、能力类别、划分策略及用途快照；具体SOP要求映射仍放AI能力配置/现场评测。
- 缺参与者或组信息可以保存准备数据，但独立测试检查不通过；页面列出具体缺失，不删除旧素材。
- 历史已训练模型使用原快照，不能通过自动迁移宣称通过新的独立划分检查。

展示各类数量、不同参与者、合法变化/负例覆盖、未完成人工标注数、泄漏风险。数量不足显示需补采，不生成保证精度的结论。

验收：同次演练两路视频不会落在训练和测试两边；当前标注修改不会悄悄改变已训练快照；测试用完后不可仍称未见数据。

## 10. 模型训练与发布：真实证据取代演示指标

### 10.1 训练页

保留已有任务配置与日志，新增模型实际标识/权重来源、输入类型（RGB；可选RGB＋关键点）、裁剪/采样配置、数据版本、评测方案、许可与适用条件记录、来源标识。

若基础模型不需要本平台训练，应走“已有模型适配/验证”候选路径，不伪造一个成功训练任务来满足旧门槛。其产物标识、输出契约、独立测试和现场验证同样必需。

任务失败可重试新任务，旧日志保留；缺 GPU/服务/素材真实文件时显示不可运行，不用计时器伪装真实训练。原型模拟任务可继续提供交互演示，但明确模拟。

### 10.2 发布页

发布检查扩展为：产物有效、来源/许可记录齐全、输出兼容、独立数据测试、对应任务评测、未知与负例覆盖、可复现环境。动作显示事件级指标与分类指标分别；纯物体显示检测指标；不强迫不同能力共用一个准确率。

发布候选含两种来源：自训练产物、基础模型适配产物。内部保留模型文件标识与验证记录，用户只维护当前模型，旧的 `trainingTaskId` 继续保留，新候选不靠捏造它绑定。

“发布到能力库”与“在工位启用”继续分开。重新发布显示受影响配置，并使对应工位待重新验证；运行中会话保留快照。回退由实施人员按内部发布记录恢复当前模型，再核对现场验证，不新增模型版本列表、兼容性决策或普通教师回退界面。

演示候选不能在真实数据模式发布为可用；历史只有演示结果的模型显示“历史原型记录”，不能自动补为真实已验证。

验收：一个训练完成但未独立测试的真实模型不能启用；一个未经训练但有来源且完成验证的基础模型不必伪造训练；发布不修改正在考试Session。

## 11. 工位与现场验证

第一阶段记录固定机位、实际视频文件/流源、分辨率/编码/模型采样配置、照明、ROI和计算环境版本。沿用矩形ROI，界面百分比与模型坐标归一化由适配层统一换算，不能混用比例与像素。

现场验证保留原八类场景，并加入：

- 合法变化：左右手、快慢、自然停顿。
- 伪完成：桌上手套、只拿工具、表笔悬空/错点。
- 真实中断与恢复：半途停下、重复尝试、错误后纠正。
- 连续运行：空闲背景、切换步骤、工具移走、状态失效。

每案例保存要求、预期、真实/模拟来源、样本/录像引用、模型/配置版本、执行人、实际事件与教师结论。不能只填“通过”作为实测证据。

汇总分为“场景检查完成”和“独立批量评测通过”；两者同时满足约定条件，才开放相应判断项。若只支持全工位启用，第一版可在已启用工位内按判断项配置实际自动/辅助模式，不能让一个合格项代表全部项。

第一阶段配置多相机集合的兼容数据结构，前台先保留固定工作台单视角简洁操作。第四批再开放区域与多视角编辑，主/辅助/备用是角色而不是相机数量限制。

验收：调整机位使依赖ROI的项需重新验证；未受影响人工项仍能使用；模拟八场景不能通过真实上线；无完整证据的失败案例可重试且旧记录保留。

## 12. 教师监控、结果与学生会话

### 12.1 教师监控

保留大视频、横向SOP卡和右侧步骤详情。增加业务可读信息：已观察事实、缺少的证据、无法判定原因、完成来源、持续状态变化、待教师事项。

管理员诊断页显示技术细节；教师只显示“手部遮挡”“动作尚未完整”“无法关联当前学生”等业务原因，不显示阈值与部署参数。

事件时间轴：事实发生、动作结束、规则确认、学生提交、教师确认各自记录时间。实际动作窗口与模型输出窗口不能混作同一个时间；多个命中合并为同一次事件。

学生已做下一步但当前步未自动确认时，记录事实并提示核对，不自动宣告错序；错序结论取决于教师窗口与规则。持续防护变化进入独立提醒，不只依赖当前Step。

### 12.2 结果状态与评分矩阵

| 判定状态 | 显示 | 默认评分处理 | 步骤推进/复核 |
| --- | --- | --- | --- |
| 证据支持完成 | AI证据完成，附片段 | 按原评分规则 | 可按现有自动完成策略推进 |
| 学生提交，缺自动证据 | 学生已提交，未自动确认 | 按规则保分 | 按现有提交/教师流程；记录来源 |
| 不确定/不可见 | 未判定，附原因 | 保分 | 不伪造完成事实；教师可复核 |
| 系统异常 | 评价降级，显示影响区间 | 不因故障扣分 | 沿用故障处理与人工流程 |
| 教师确认 | 教师结论、理由、证据/缺证说明 | 有理由审计后改判或保分 | 记录复核版本 |
| 安全候选 | 待安全处置 | 不以未知自动扣分 | 沿用现有暂停与候选处置 |
| 已确认安全红线 | 明确安全事件与处置 | 按教师标准与现有安全规则 | 保持阻断/暂停与人工处理 |

报告汇总分开显示：计划自动评价范围、实际有证据完成、未知、教师项、教师复核。覆盖统计按明确分母计算，缺少权重时显示项数，不能随意加权。

报告回放支持跳到相关片段，缺失媒体显示不可用与原判定信息；录像到期后保留评分、版本和审计，不生成虚假可播放链接。已发布成绩不被后来离线AI分析自动覆盖；新分析形成建议，教师走原复核流程。

### 12.3 学生端与考试

练习可提示“请按要求继续”“关键操作被遮挡，请调整到可见位置”等教师认可内容；无法判定不提示“你做错了”。不得向学生解释算法阈值。

考试学生端继续隐藏标准内容、实时正确性、扣分/分数和置信度；只有安全与系统运行必要提示允许显示。不同页面、刷新恢复与大屏汇总都需同样过滤。

验收：满分但未知的报告明确保分来源；教师改判保留理由、证据、操作者、时间及影响预览；考试所有入口不泄露实时判断。

## 13. 新数据对象与事件契约

具体数据库设计由研发决定，产品至少需要下列可追溯对象：教师可见要求、采集批次/Session数据组、标注建议任务、正式标注修订、锁定数据集、模型候选及评测、现场验证、观察事实、动作事件、持续状态、判定与复核。

观察/事件契约最低内容：

| 内容 | 要求 |
| --- | --- |
| 来源与身份 | 真实/模拟、Session、学生、相机/区域、人物关联状态 |
| 观察事实 | 对象/动作、可见性、开始结束时间、帧/窗口来源 |
| 事件聚合 | 独立事件ID、是否完整、是否重复/纠正、关联对象 |
| 证据 | 真实媒体引用与时间区间；无证据显式空缺 |
| 内部追溯 | SOP ID与锁定标准快照、当前能力配置快照、模型文件/任务标识、ROI/采集配置指纹、输出结构 |
| 下游判定 | 候选/确认/未知、适用要求、评分与完成用途；安全候选另记 |

一个事实可以映射多个教师要求，但不能重复产生相同扣分或动作计数。事件重试、乱序到达、离线重分析都要防重复；生产后端拒绝跨Session/版本不匹配结果，不能覆盖历史。

## 15. 分批验收与回归

每批执行相关规则测试和构建；已有业务/考试/数据迁移测试保留。测试集中在错误可能改变评分、正式标签、数据隔离和版本的地方，不为每个静态字段写重复测试。

第一批：合法变化不判错、未知保分但不自动完成、复制创建新SOP不修改旧会话、考试隐藏。

第二批：不完整负例保留、建议须经人工保存后进入训练、无目标主动确认、当前标签修改不覆盖历史训练快照、Session/参与者划分无泄漏、刷新与失败不丢数据。

第三批：真实/模拟门槛分离、基础模型验证路径无需伪造训练、事件聚合和重试防重复、持续状态失效、断流降级、模型切换与会话锁定、教师复核审计。

第四批：相机集合迁移、区域覆盖、多视角证据和人物交接，某一路缺失时仅受影响要求按规则降级。

原型验收证明交互与业务规则可执行，真实算法验收另见文档03；不能用前端测试通过替代模型现场效果。
